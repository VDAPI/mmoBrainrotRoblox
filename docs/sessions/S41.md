## B. Reguły planera w TS (`wiki/src/lib/skills.ts`, czyste funkcje)

`pointsAt(level)` (z `pointsByLevel`), `spent(build)`, `free(build, level)`, `canAdd(cls, build, level, id) → { ok, reason?, detail? }` w kolejności gry (`maxLevel` → `noPoints` → `level` → `requires`), `canRemove(build, id)` (ranga > 0 i żadna nauczona umiejętność nie traci wymagania), `validate(build, level)` (suma ≤ punkty, każda ranga ≤ `maxLevel` i jej `requiredLevel` ≤ poziom, każde `requires` spełnione), `requiredCharLevel(build)` (najmniejszy poziom, na którym build jest poprawny), `maxReachableRank(skill, maxLevel)`, `nodeState(...)` → `locked` (odblokowanie albo wymaganie niespełnione) | `available` | `partial` | `max` (+ `invalid`, gdy ranga wymaga wyższego poziomu niż wybrany), `encodeBuild`/`decodeBuild`. **Kod buildu:** `<CLASSID wielkimi><poziom>-<rangi>`, rangi w kolejności `order`, jeden znak na umiejętność (`0`–`9`, `a` = 10), myślnik co 7 znaków, np. `MAGE34-a305000-0300000`; dekoder ignoruje myślniki i wielkość liter, a zły kod (inna klasa, zła długość, ranga > max, poziom poza 1…max) zwraca błąd z powodem, nigdy wyjątek.
