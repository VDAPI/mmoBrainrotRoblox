### A. Generator: rodzaj potwora i liczba zabić (`Logic/ContractGen`, `Data/Quests/Contracts.RULES`)

1. Wybór łowiska bez zmian (te same kary rotacji, ta sama kolejność), **potem wybór rodzaju** z `area.kinds` (tylko zwykłe rodzaje; Elity i Elity II nigdy nie są celem): wynik najmniejszy `penalty.kindPrevious` (ten sam rodzaj co L − 1, start 100) + `penalty.kindPerUse × użycia rodzaju dotąd` (start 3); remis → niższe id. Deterministycznie, bez `Rng`. Nowe pola w `RULES.penalty`.
2. **Liczba zabić na rodzaj:** `max(RULES.minKindKills, round(killsAt(L) × udział))`, gdzie `udział` = udział rodzaju wśród zwykłych potworów łowiska (funkcja z `AreaSpawns` / `AreaRates`, inaczej `1 / #kinds`), `minKindKills` start 6. Kotwice `kills` bez zmian — czas zlecenia zostaje mniej więcej jak w S99 (linia w DECYZJE). Gdy model F pokaże, że czas zlecenia rośnie > 20% (rodzaj rzadszy niż średnio), strój `minKindKills` / zaokrąglenie, nie kotwice EXP.
3. Cel: `objectives = { { type = "kill", n, monster = <kindId>, area = <areaId> } }` — rodzaj **i** łowisko (potwór tego rodzaju z innego łowiska się nie liczy; linia w DECYZJE: „pole `area` zostaje, prowadzenie i mapa wskazują jedno miejsce”). Wariant nieustawiony: Elita tego samego rodzaju (jeśli taka istnieje w danych) też się liczy.
4. `ContractGen.report`: dopisz użycia rodzajów i najdłuższą serię jednego rodzaju. `lune run tools/contracts_gen.luau` → nowa lista `GENERATED`.
5. Typ `Types.ContractQuest` / `QuestTypes.Objective` bez nowych pól (pole `monster` już jest); `QuestTypes.Reward` dostaje `marks: number?` (E1).

### B. Stan: wiele aktywnych naraz (`Logic/Contracts`, zapis, migracja)

1. **Nowy kształt** `character.quests.contract = { done: number, extra: { number }, active: { { level: number, progress: { number } } }, marks: number, auto: boolean }`:
   - `done` = najwyższy poziom, do którego **wszystkie** zlecenia są oddane (ciągły prefiks); `extra` = posortowane poziomy > `done` oddane poza kolejnością (po każdym oddaniu kompaktowane: `done` przesuwa się, póki `done + 1` jest w `extra`);
   - `active` = przyjęte, nieoddane (po jednym na poziom, posortowane rosnąco); `marks` = saldo Znaków Łowcy (E1); `auto` = `true` po pierwszym przyjęciu (B4).
   - **Decyzja (linia w DECYZJE): Znaki na postaci, nie na koncie** — zlecenia są postaci, skrzynie dla klasy postaci, a konto pozwoliłoby farmić tanie zlecenia 1–20 na drugich postaciach dla głównej.
2. `Contracts.stateOf(quests)` z ochroną typów (śmieci → wartości domyślne, wpisy `active` o złym poziomie, zdublowane albo już oddane odrzucone, `progress` nie-tablica → zera, `marks` całkowite ≥ 0). Nowe / zmienione funkcje: `isDone(state, level)`, `eligible(state, charLevel) -> { ContractQuest }` (poziom ≤ postaci, nieoddane, nieaktywne), `activeList(state) -> { { contract, entry } }`, `complete(state) -> { ... }` (gotowe do oddania), `canAccept(state, charLevel, npcId) -> (boolean, string?)` (`"none" | "level" | "giver"`), `giversOf` / `isGiver` (dochodzi `huntmaster`, E3), `backlog` (eligible + aktywne nieukończone), `upcoming(state, count)` (następne powyżej poziomu postaci), `allDone`, `credit(state, data) -> { level }` (które aktywne zlecenia dostają zabicie — przez `QuestLogic.amount`, bez kopii reguł). **Bez limitu liczby aktywnych** (prośba właściciela).
3. **Migracja** (następny wolny numer w `AccountSchema`, idempotentna): stary kształt `{ done, active? }` → `{ done, extra = {}, active = { … }, marks = <retro>, auto = done > 0 or active ~= nil }`; stare aktywne zlecenie przechodzi z postępem `min(stary postęp, nowe n)` (stary cel liczył każdy potwór; linia w DECYZJE). **Retro Znaki:** `marks = Σ Contracts.marksFor(L)` dla `L = 1 … done` (bez kamieni milowych; postać nie traci za to, że oddała zlecenia przed S134k). Szablon nowej postaci: `{ done = 0, extra = {}, active = {}, marks = 0, auto = false }`. Testy migracji w `contracts.spec`.
4. **Samo przyjmowanie:** gdy `auto == true`, awans postaci (`LevelService.LeveledUp`) przyjmuje zlecenie nowego poziomu od razu (toast `contract.next` jak dziś); oddanie przyjmuje nowo dostępne (jeśli jakieś są). Pierwsze przyjęcie zawsze przy NPC.

### C. Serwer (`ContractService`, `QuestService`, `Net/Definitions`)

1. `ContractService.Handle(player, "kill", data)`: postęp **każdego** aktywnego zlecenia, któremu `QuestLogic.amount` daje > 0 (rodzaj i łowisko), jednym `PlayerStateService.Set` gałęzi `active` (nowa tablica). Toast `contract.ready` dla każdego zlecenia, które właśnie się zakończyło (przy wielu naraz jeden toast `contract.readyMany` „Gotowe zlecenia łowieckie: {n}”). Drużyna jak dziś (kredyt dla każdego członka).
2. Remote'y (`Net/Definitions.luau`): `ContractAccept(npcId)` → **przyjmuje wszystkie** dostępne zlecenia, które ten NPC wydaje (tablica i Łowczy: wszystkie; zwiadowca: zlecenia swojego regionu), zwraca `(true, nil, count)`; nowy `ContractAcceptOne = { kind = "function", dir = "c2s", rate = 4, args = { "string", "integer" } }` (`npcId`, poziom; pojedyncze przyjęcie z dziennika / tablicy); `ContractTurnIn(npcId)` → **oddaje wszystkie** ukończone zlecenia, które ten NPC przyjmuje („Oddaj wszystkie”), zwraca sumę nagród. `ContractAbandon(level)` (`rate = 4`): porzuca aktywne (postęp przepada, zlecenie wraca do dostępnych) — do porządkowania listy.
3. **Oddanie wielu naraz** bez yieldów: suma EXP (jedno `LevelService.GiveExp` na zlecenie, po kolei rosnąco — awans w trakcie liczy się poprawnie), złota, Znaków, przedmiotów kamieni milowych. Przedmioty: co się mieści → plecak, reszta → poczta systemowa (wzór S100 / S125), **nigdy odmowa całego oddania** (zmiana wobec S99: linia w DECYZJE). Jeden `CombatFx` z sumą (`exp`, `gold`, `marks`), jeden `QuestCompleted` z kluczem `contract.titleMany` „Zlecenia łowieckie: {n}” (przy jednym — jak dziś), log i `Analytics.custom(player, "ContractTurnIn", n)`.
4. Admin (`Data/AdminCommands`, `src/server/Admin/Quests.luau`): `/contract set <L>` dopasowany do nowego stanu (oddane < L, aktywne L), `/contract all` (przyjmij wszystkie bez NPC), `/contract finish [L|all]` (ukończ postęp), `/marks <n>` (dodaj / odejmij Znaki) + `admin.usage.*` PL i EN.

### D. Interfejs: dziennik, tablica, tracker, mapa

1. **Dziennik, zakładka „Łowieckie”:** nagłówek (oddane / 99, saldo Znaków ze znakiem waluty, aktywne, gotowe), przyciski „Przyjmij wszystkie ({n})” i „Oddaj wszystkie ({n})” aktywne tylko przy NPC wydającym (inaczej podpowiedź `contract.whereTurnIn` „Oddasz przy tablicy zleceń, u Łowczego albo u zwiadowcy regionu”). Lista **zgrupowana po mapie, potem łowisku** (nagłówek grupy: nazwa łowiska, poziom, liczba zleceń), w grupie wiersze: „Ubij {n}× {rodzaj}” (nazwa z `Monsters` `nameKeys.normal`), postęp, poziom, nagroda (EXP, złoto, Znaki), „Śledź” / „Porzuć”. Gotowe na górze grupy z zielonym znakiem. Sekcja „Dostępne” (do przyjęcia, zwinięta) i „Następne” (trzy powyżej poziomu). Przewijana, PC i telefon.
2. **Tablica zleceń** (`QuestBoard`): karta zleceń łowieckich pokazuje liczby (dostępne / aktywne / gotowe) i dwa przyciski jak wyżej zamiast jednego zlecenia.
3. **Tracker HUD:** najwyżej `Config.Quests.trackerContracts` (start 3) zleceń: śledzone najpierw, potem gotowe, potem z bieżącej mapy wg odległości do łowiska; pod spodem linia `contract.trackerMore` „+{n} zleceń łowieckich (J)”. Rodzaj i łowisko w jednej linii, postęp `{a}/{n}`.
4. **Mapa i prowadzenie:** karta zlecenia na mapie świata (`WorldMap/Cards`) z rodzajem potwora (nazwa, poziom, ikona rodziny / portret jak w `CreatureCards`), łowiskiem i postępem; „Prowadź” (`NavController.Guide`) do łowiska; przy wielu aktywnych na jednym łowisku jedna karta z listą. Strzałka trackera prowadzi do łowiska śledzonego zlecenia. Znaki nad NPC (`npcmarks.spec`): „?” przy gotowych, „!” przy dostępnych — dla tablicy, Łowczego i zwiadowcy regionu.
5. `QuestText.contractTitle` / `contractTarget` z rodzajem; Locale PL i EN.

### E. Znaki Łowcy i sklep Łowczego

1. **Znaki za zlecenie:** `RULES.marks = { base = 2, per10 = 1, milestone = 10 }` (start; model F stroi): `marks(L) = base + floor(L / 10) + (milestone, gdy L % 10 == 0)` — zlecenie 1 daje 2, 45 daje 6, 99 daje 11; suma 1–99 ok. 740. `Contracts.marksFor(L)` jedyne źródło; `ContractGen.build` wpisuje `reward.marks`. Nagroda EXP / złoto / kamienie milowe **bez zmian** (poziom zlecenia, punkt 4 prośby).
2. **Dane sklepu** `src/shared/Data/HuntShop.luau` (wzór `Data/Arena.SHOP`): `{ key, kind = "item" | "chest" | "cosmetic", id, n, price, group = "consumable" | "essence" | "chest" | "cosmetic", minLevel?, weeklyLimit? }`. Start:
   - mikstury (najlepsza, jaką postać już kupi u alchemika na swój poziom: grep progów `LoginReward.potionQuality`), błogosławieństwa szczęścia / EXP do Heroicznych, Kamienie Powrotu, Kamienie Mapy;
   - esencja: pył 10 szt. za 8 Znaków, odłamek za 6 (od 45.), kryształ za 15 (od 70.), **limit tygodniowy** na każdą (np. 30 pyłu / 10 odłamków / 3 kryształy — model F);
   - **Skrzynia Łowcy** (Unikat dla klasy, poziom postaci, związany) za 60 Znaków; **Heroiczna Skrzynia Łowcy** (Heroik dla klasy, związany) za 200, `weeklyLimit = 1`; **nigdy Legendarny ani Mityczny**;
   - kosmetyki (E5).
   - Ceny i limity tylko tu, wpis w księdze `{ session = "S134k", why }`.
3. **Łowczy** (`Data/Npcs`: `townsfolk("huntmaster", …, { services = { "talk", "quests", "huntshop" } })`, miejsce przy tablicy zleceń w `Data/Town/npcExtra`, nazwa „Łowczy Bartosz” / „Huntmaster Bartosz”, powitanie w tonie zwiadowców). Przyjmuje i wydaje zlecenia jak tablica (`Contracts.giversOf`).
4. **Logika i serwer:** `Logic/HuntShop.canBuy(entry, state, charLevel, week) -> (boolean, string?)` (saldo, `minLevel`, `weeklyLimit` z licznikiem `contract.shopWeek = { week, counts }` na postaci — w tej samej migracji), remote `HuntShopBuy = { kind = "function", dir = "c2s", rate = 3, args = { "string", "string", "integer" } }` (`npcId`, `key`, ilość ≥ 1, ≤ stosu), `ContractService` (albo nowy `HuntShopService`, jeśli `ContractService` przekroczy ok. 450 linii): blisko `huntmaster`, `canBuy`, pobranie Znaków, przyznanie (pełny plecak → odmowa `inventory.full` przed pobraniem; skrzynia to przedmiot do otwarcia albo losowanie od razu — wybierz to, co robi skrzynia S100, linia w DECYZJE), bez yieldów. Wszystko z sklepu **związane** (`bindOnPickup`), sprzedaż u kupca za 0 / brak skupu.
5. **Kosmetyki** (`Data/Cosmetics`, `obtain.hunt = "shop"`): tytuł „Łowca Nagród” (200) i ramka portretu „Trofeum” (400), proceduralne jak kosmetyki areny (brak obrazków → wpis w „Niedokończone”); tytuł „Mistrz Łowów” za oddanie wszystkich 99 (nagroda zlecenia 99, nie sklep).
6. **Okno sklepu:** zakładki grup (Mikstury i kamienie / Esencja / Skrzynie / Kosmetyki), saldo Znaków, cena, limit tygodnia „{n}/{max}”, przyczyna niedostępności (`huntshop.error.*`), potwierdzenie zakupu skrzyni. Otwierane z dialogu Łowczego (usługa `huntshop`) i przyciskiem w zakładce „Łowieckie” przy Łowczym. Wzór: zakładka sklepu `ArenaWindow` (wspólny kawałek wyciągnij zamiast kopiować, jeśli to proste).
7. **Bez pay2win:** Znaki nie są w sklepie premium ani w `Data/Products`; żaden produkt za Robux / Smoczą Walutę ich nie daje (`paywall.spec`: dopisz `huntmarks` do listy walut, których nie da się kupić, jeśli taka lista istnieje — grep).

### F. Model (`tests/Balance.luau`, `tests/balance.spec.luau`, `tools/balance_report.luau`)

1. `Balance.contractTime(level)` (czas zlecenia z nowym `n` i udziałem rodzaju, przez istniejący model zabójstw / h łowiska) i `Balance.huntMarks(level)` (Znaki / h przy robieniu zleceń swojego poziomu).
2. Wiersze `S134k.*` (tabela `Balance.S134k`):
   - `time`: czas zlecenia na rodzaj ≤ 1,2× czasu zlecenia S99 tego poziomu (każdy poziom 4–99);
   - `value`: wartość w złocie wszystkiego, co da się kupić za Znaki z jednej godziny zleceń (mikstury, esencja po `Balance.materialPrices`), to **5–15%** dochodu złota tej godziny (motywacja, nie druga gospodarka);
   - `essence`: esencja z limitów tygodniowych przy 14 h gry tygodniowo ≤ **10%** podaży esencji pasma (`materialSupply`) — ulepszanie i przemiana S134j zostają na łupie;
   - `chest`: Skrzynia Łowcy kosztuje ≥ 2 h zleceń swojego pasma; Heroiczna 1 / tydzień; oczekiwana liczba Heroików z łupu / tydzień przy 14 h ≥ 1 (skrzynia nie wyprzedza łupu — gdy model łupu nie ma tej funkcji, wiersz w raporcie z powodem);
   - `retro`: suma retro Znaków z migracji dla postaci L 99 = suma `marksFor(1..99)` bez kamieni milowych.
3. EXP zleceń bez zmian (budżet S109); `quest_budget` przelicza tylko to, co wynika ze zmiany czasu zleceń (jeśli w ogóle).
4. Raport: sekcja „Zlecenia łowieckie i Znaki (S134k)” w `tools/balance_report.luau` i `docs/BALANS.md` (Znaki na L, czas zlecenia S99 → S134k, wartość godziny, ceny), księga „Zmiany danych” (S134k).

## Prośba właściciela (dla kontekstu)

> „łowieckie, gdy zabijasz innego moba niż każe, to zalicza; moby które trzeba zabijać w questach są z tyłu w porównaniu do tego co możemy, więc fajnie jakby fajne nagrody za te questy były, żeby zmotywować gracza do robienia ich + niech da się odebrać ich wiele na raz” (ProjektG, 2026-10-15)

Odpowiedzi właściciela (2026-10-15):
1. Cel = konkretny rodzaj potwora (np. „15 Dzików”), liczy się tylko ten rodzaj; generator wybiera rodzaj obecny na łowisku, z rotacją.
2. Wiele zleceń naraz bez limitu: wszystkie dostępne (poziom ≤ poziomu gracza) mogą być aktywne jednocześnie i oddane jednym kliknięciem („Oddaj wszystkie”); zabicia liczą się do każdego pasującego aktywnego.
3. Lepsze nagrody przez nową walutę zleceń (Znaki Łowcy) wymienianą u Łowczego na przedmioty (mikstury, esencja, skrzynie Unikat / Heroik dla klasy, kosmetyki) — bez przewagi ponad łup; ceny w danych, okno sklepu; miejsce zapisu waluty i migracja — decyzja sesji.
4. Poziom nagrody zostaje poziomem zlecenia (bez skalowania do poziomu gracza).
