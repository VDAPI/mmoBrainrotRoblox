## Kontekst

Właściciel w ankiecie DESIGN-15 wybrał z pomysłów dodatkowych **nagrodę za logowanie** (cytat na końcu). Kontrakt (`docs/DESIGN-15.md` §5) ustala: seria 7 dni **na konto**, pierwsze wejście danego dnia (UTC) dowolną postacią daje okno nagrody dnia N, odbiera ta postać, nagroda skalowana jej poziomem; dni 1–6: złoto, mikstury, błogosławieństwo, pył esencji, kamień powrotu; dzień 7: skrzynia (przedmiot do Heroicznego na poziom postaci + błogosławieństwo Unikatowe); po dniu 7 seria wraca do 1; opuszczenie pełnego dnia zeruje serię, co widać w oknie („Jutro dzień 4. Przerwa zeruje serię”); zapis `account.login = { day, last }`; bez premium i Robuxów. Nagroda ma dawać powód do codziennego wejścia, ale nie zmieniać tempa gry (poziomy) ani wyraźnie gospodarki: to dodatek rzędu kilkunastu–kilkudziesięciu minut dochodu na tydzień, bez EXP.

Czyste dane, bez funkcji (zrzut księgi woła funkcje danych na `LEDGER_LEVELS`, a tu nie są potrzebne), zamrożone. Liczby poniżej to **punkt startowy** (policzony na dochodzie z diagnozy S84 J: tydzień ok. 0,45 h na 20., 0,38 h na 45., 0,31 h na 70., 0,24 h na 99.; najdroższy dzień ≤ ok. 0,11 h): po G2 stroisz je do celów G3 (najpierw pasma mikstur, potem `gold.perLevel`), a każdą zmianę opisuje ten sam wpis prefiksowy księgi.

```lua
--!strict
-- Daily login reward (DESIGN-15 §5, S100): a 7-day streak per account in UTC days; the character that claims the
-- day gets it, scaled by its level. Pure data; Logic/LoginReward builds the contents and rolls the day 7 chest.
-- Balance numbers: tools/balance_reasons.luau (BALANCE_MODULES), targets in tests/balance.spec.luau ("Login reward").

export type DayDef = {
	gold: number?, -- multiple of the gold unit (gold.base + gold.perLevel x level)
	potions: number?, -- multiple of the potion count of the quality (HP + the class resource)
	essence: number?, -- multiple of the essence count of the level band
	stones: number?, -- Return Stones
	blessing: number?, -- blessing rarity (1 Common, 2 Unique) of the class line
	chest: boolean?, -- day 7: one Unique / Heroic item for the level and class
}

return table.freeze({
	DAYS = 7,
	-- Gold unit at level L: base + perLevel x L, rounded to 5. A daily contract pays 50 + 30 x L (Quests/Daily).
	gold = table.freeze({ base = 10, perLevel = 8, round = 5 }),
	days = table.freeze({
		{ gold = 1, stones = 2 }, -- 1
		{ potions = 1 }, -- 2
		{ gold = 1, essence = 1 }, -- 3
		{ blessing = 1, stones = 1 }, -- 4
		{ gold = 1.5, potions = 1 }, -- 5
		{ gold = 1, essence = 1 }, -- 6
		{ gold = 1.5, blessing = 2, chest = true }, -- 7: the chest (DESIGN-15 §5: up to Heroic + a Unique blessing)
	} :: { DayDef }),
	-- Potion quality by character level (the highest band with from <= level whose potion the level may drink,
	-- Logic/Potions.canDrink, S87) and potions of each kind for potions = 1. Greater (900) from 60 and no Mighty
	-- (3000): at buy price two Mighty potions alone are ~0.2 h of income at 70 (day cap 0.12 h, G3).
	potionBands = table.freeze({
		{ from = 1, quality = 1, n = 5 },
		{ from = 12, quality = 2, n = 3 },
		{ from = 35, quality = 3, n = 1 },
		{ from = 60, quality = 4, n = 1 },
	}),
	-- Essence by level: the essence the character's upgrades need now (+1..+3 dust, +4..+6 shard, +7..+9 crystal).
	essenceBands = table.freeze({
		{ from = 1, id = "essence_dust", n = 3 },
		{ from = 20, id = "essence_shard", n = 2 },
		{ from = 45, id = "essence_crystal", n = 1 },
	}),
	-- Blessing line of each class (never "fortune": the login reward gives no EXP bonus, DESIGN-15 §3.2 pace).
	classLine = table.freeze({ Warrior = "warrior", Hunter = "hunter", Mage = "sage", Cleric = "guardian" }),
	chest = table.freeze({
		rarity = table.freeze({ [2] = 65, [3] = 35 }), -- Rarities.UNIQUE / HEROIC weights
		classBias = 1, -- always an item the class can wear when the tier has one (Loot.pickItem)
		bound = true, -- bound to the character (no alt-account farming for the market)
	}),
})
```

Uwagi:
- Klucze rzadkości jako liczby (`[2]`, `[3]`), bo `Data` nie powinno wymagać `Data/Rarities` tylko dla stałych; test (`loginreward.spec`, T5) sprawdza, że `2 == Rarities.UNIQUE` i `3 == Rarities.HEROIC` i że żaden klucz nie przekracza `Rarities.HEROIC` („do Heroicznego”).

### B. Czysta logika

**B1. `src/shared/Logic/LoginReward.luau` (nowy, ok. 150 linii).** Wymaga `Data/LoginReward`, `Data/Items`, `Data/Classes`, `Data/LootTables`, `Logic/Loot`, `Logic/ItemRoll`, `Logic/Potions`, `Logic/Rng` (typ). Bez API Roblox.

```lua
export type State = { day: number, last: number } -- day: last claimed streak day 0..7; last: UTC day of that claim (0 = never)
export type Status = {
	claimable: boolean, -- a reward waits today
	day: number, -- the day claimable today, or the day claimed today
	claimedToday: boolean,
	resets: boolean, -- a missed day reset a running streak (claimable day is 1 because of a break)
	nextDay: number, -- the streak day of the next UTC day if the player keeps the streak
}
export type Contents = { exp: number, gold: number, items: { { id: string, n: number } }, chest: boolean }

function LoginReward.sanitize(raw: any): State
function LoginReward.status(state: State, today: number): Status
function LoginReward.claim(state: State, today: number): (State?, number?) -- new state and the claimed day; nil when nothing to claim
function LoginReward.goldAt(day: number, level: number): number
function LoginReward.potionQuality(level: number): number
function LoginReward.contents(day: number, level: number, classId: string): Contents
function LoginReward.week(level: number, classId: string): { Contents } -- days 1..7, the window's preview and the balance block
function LoginReward.rollChest(level: number, classId: string, rng: Rng.Rng): Loot.ItemDrop?
```

Zasady:
- `sanitize`: tabela inna niż `{ day: number, last: number }` → `{ day = 0, last = 0 }`; `day` = `math.clamp(math.floor(day), 0, DAYS)`, `last` = `math.max(0, math.floor(last))`. Serwis i klient zawsze czytają stan przez `sanitize` (zapis z błędem albo ręcznie ustawiony przez admina nie wywraca okna).
- `status(state, today)`:
  - `last == 0` (nigdy nie odebrano) → `claimable = true`, `day = 1`, `resets = false`;
  - `last == today` → `claimedToday = true`, `claimable = false`, `day = state.day`;
  - `last == today − 1` → `claimable = true`, `day = state.day % DAYS + 1` (po 7 znów 1, to nie jest przerwa), `resets = false`;
  - `last < today − 1` → `claimable = true`, `day = 1`, `resets = state.day >= 1 and state.day < DAYS` (przerwa przerwała trwającą serię; po pełnym tygodniu seria i tak zaczyna się od 1, więc bez komunikatu o zerowaniu);
  - `last > today` (zegar cofnięty przez `/time`, inny serwer z przesuniętym zegarem) → traktuj jak `claimedToday` z `day = state.day`, bez odbioru: zegar w tył nigdy nie daje drugiej nagrody (test).
  - `nextDay` = `day % DAYS + 1` przy `claimedToday`, inaczej `day % DAYS + 1` też (dzień po odebraniu dzisiejszego); okno używa go w zdaniu „Jutro dzień {next}”.
- `claim(state, today)`: gdy `status.claimable`, zwraca `{ day = status.day, last = today }` i `status.day`; inaczej `nil, nil`. **Seria liczy się w chwili odbioru**: dzień, w którym gracz wszedł, ale nie odebrał (zamknął okno i wylogował się), jest dniem bez nagrody i przerywa serię (DESIGN-15 milczy: decyzja w J). Okno samo się otwiera, a przycisk HUD ma odznakę, więc to rzadki przypadek.
- `goldAt(day, level)`: `0`, gdy dzień nie ma `gold`; inaczej `round5(gold × (base + perLevel × L))` (`math.floor(x / round + 0.5) × round`), `L` = `math.clamp(math.floor(level), 1, Config.MaxLevel)`.
- `potionQuality(level)`: najwyższe pasmo z `from <= level`, którego mikstura HP (`Items.get("potion_hp_" .. quality)`) spełnia `Potions.canDrink(def, level)` (S87, progi 45 / 70); bez S87 (brak `canDrink`) zostaje samo pasmo. Liczba sztuk każdego rodzaju = `max(1, round(band.n × day.potions))`.
- `contents(day, level, classId)` w stałej kolejności (test i UI na niej polegają): złoto; mikstury `potion_hp_<q>` i `potion_<resource>_<q>` (`Classes.get(classId).resource`; nieznana klasa → tylko HP); esencja pasma (`max(1, round(n × day.essence))`); `stone_return × stones`; `blessing_<classLine[classId] or "guardian">_<blessing>`. `exp = 0` zawsze (kształt `Quests.Reward`, więc `QuestRewards` je pokazuje), `chest = day.chest == true`. Każde `id` istnieje w `Data/Items` (test). Przedmiot skrzyni **nie** jest w `items` (losuje go serwer przy odbiorze).
- `rollChest(level, classId, rng)`: `ilvl = ItemRoll.dropLevel(level, rng)`, `defId = Loot.pickItem(LootTables.bossSlots, ilvl, chest.classBias, classId, rng)`, rzadkość `rng:weighted(chest.rarity)`; wynik `{ defId, ilvl, rarity, forClass = classId }` albo `nil`, gdy progu brakuje (wtedy serwer daje zamiast przedmiotu podwójną esencję pasma i loguje ostrzeżenie; test sprawdza, że na poziomach 1–100 każdej klasy dla 50 ziaren wynik nigdy nie jest `nil`). Ta sama droga co gałąź Unikat / Heroik bossa (`Loot.rollBossItem`), więc przedmiot ma poziom, klasę i rzadkość jak z dropu, a linie losuje `ItemRoll.rollItem` na serwerze.
