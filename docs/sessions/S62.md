### B. `src/shared/Logic/ItemRoll.luau`

1. **Klasy puli** (STATY 2B):
   ```lua
   -- S62 (STATY 2B): a base shared by classes (mace1h, shield) rolls for the class it dropped for; class-free items
   -- (jewellery) for `forClass` when known.
   local function classesFor(def: Items.ItemDef, forClass: string?): { string }?
   	if def.classes then
   		if forClass and table.find(def.classes, forClass) then
   			return { forClass }
   		end
   		return def.classes
   	end
   	return if forClass then { forClass } else nil
   end
   ```
   Używają jej `bonusPool`, `legendaryPool` i `mythicPool` (`forClass` spoza `def.classes`, np. łup innej klasy, daje `def.classes` jak dziś).
2. **Wagi:** `function ItemRoll.poolWeights(defId: string, forClass: string?): { [string]: number }`: pula grupy po `filtered(…, classesFor(def, forClass))`, waga `ItemTraits.weight(def.type, id, classId)`, gdzie `classId` to jedyna klasa z `classesFor` (inaczej `nil`); w wyniku tylko wagi > 0. `ItemRoll.bonusPool(defId, forClass)` zwraca dalej listę w kolejności puli, ale tylko linii z wagą > 0 (z niej korzystają `tests/Balance.poolFor`, wiki i `balance.spec`).
3. **`rollItem`:** zamiast `shuffle` (199–206) najpierw `count = rng:int(bonusMin, bonusMax)` (gdy `bonusMax > 0`), potem `count` razy `local id = rng:weighted(remaining)`, `remaining[id] = nil` i wartość `rollBonusValue(id, level, rarityId, rng:next())`; przerwij, gdy `remaining` jest puste. Bez powtórzeń jak dziś. Linie legendarne i mityczne zostają losowane równo (`shuffle`), tylko z `classesFor`. Komentarz: `-- S62: weighted draw without replacement (Data/ItemTraits affinity); the rng sequence changed, seeded tests that check exact lines were re-based`. Ciąg losowań się zmienia (także dla Zwykłych, które nie wołają już `shuffle`, więc np. żywioł broni Maga przy tym samym ziarnie może wyjść inny): testy statystyczne zostają zielone, a test, który sprawdza konkretny wynik przy ziarnie (linie, żywioł, kolejny rzut łupu), dopasuj i zapisz to w SESJE.
4. **Dokładne prawdopodobieństwa** dla lustra i testów:
   ```lua
   -- Exact chance (0..1) that each line is among `count` weighted draws without replacement (Rng.weighted per draw).
   function ItemRoll.inclusion(weights: { [string]: number }, count: number): { [string]: number }
   ```
   Rekurencja po kolejnych losowaniach: posortowana lista id z wagą > 0, zbiór `used` (nie zmieniaj tabeli w trakcie iteracji), `p × w / pozostała suma`; dla `count` ≤ 3 i 15 linii to ok. 2700 liści. Linie z wagą 0 dostają 0, suma wyników = `min(count, liczba linii z wagą > 0)`.
5. **Cecha:**
   ```lua
   export type TraitRoll = { id: string, def: ItemTraits.TraitDef, power: number, value: number }

   -- S62 (STATY 2A, 10): trait strength = rarity baseMul (named boss items too) x (1 + 0.06 x upgrade level).
   function ItemRoll.traitPower(rarity: number, up: number?): number
   	return Rarities.get(rarity).baseMul * (1 + Rarities.upgradeStatPerLevel * (up or 0))
   end

   -- The live trait of an item's base type, or nil (no trait, or no code yet: live = false).
   function ItemRoll.trait(item: ItemInstance): TraitRoll?
   ```
   `value = def.value × power` bez zaokrąglania (zaokrągla dopiero opis). Rozłupywacz i inne nazwane mają `rarity = MYTHIC`, więc siłę 1,22 (STATY 2A); `itemStats` dalej używa `baseMul = 1` dla ich statystyk bazy.
6. **`itemStats`:** typ `ItemStats` + `trait: TraitRoll?`. Po pętli linii: `local trait = ItemRoll.trait(item)`; `kind == "stat"` → `result.flat[def.stat] += value`; `hook` i `effect` → `result.hooks[def.hook] += value` (dla żadnej cechy z tej sesji jeszcze nie zachodzi, ale S63–S65 tylko przełączają `live`); `result.trait = trait`.

### C. Obrażenia: przebicie, odporność na krytyki, umiejętności i atak podstawowy

1. **`src/shared/Logic/Damage.luau`** (wymaga `../Data/Stats`):
