### C. AttackPose 2.0 (Logic i Data, bez API Roblox)

**C1. Format kroku w `Data/AttackMotions.luau`:**
```lua
-- One blow of a basic attack. Poses: rest -> windup (anticipation) -> pass (the contact: the pose at the server's
-- hit time, reached accelerating) -> strike (end of the blow, decelerating) -> follow (overshoot, part of the
-- recovery) -> rest. `pass` and `follow` are optional (without them: windup -> strike -> rest as in S22).
export type Step = {
	windup: number, -- seconds; the pose is reached at the end
	strike: number, -- seconds; the blow lands inside it at SERVER_HIT (the hit fraction is derived, B2)
	recover: number,
	follow: number?, -- 0..1 of `recover` spent reaching `poses.follow` (default 0.35)
	poses: { windup: Pose, pass: Pose?, strike: Pose, follow: Pose? },
	trail: { from: number, to: number }?, -- seconds of the weapon trail (default windup - 0.02 .. windup + strike + 0.04)
	sfx: { start: string?, swing: string?, release: string? }?, -- Data/Sfx keys (E4); nil = the motion's default
	hitstop: number?, -- visual freeze of this pose at the hit, seconds (<= 0.05)
}

export type Clip = { id: string, hit: string?, speed: number?, hitTime: number? }
export type ClipRef = string | Clip -- "rbxassetid://…" alone means { id = …, hit = "Hit" }

export type Motion = {
	ranged: boolean,
	steps: { Step }, -- 1..3: step 1 = the single attack, 2..3 = the combo (D); ranged motions may have one step
	clips: { ClipRef }?, -- F: real clips, clips[i] plays as combo step i (the combo then has #clips steps)
}
```
Przenieś dzisiejsze ruchy do `steps[1]` bez zmiany liczb `windup`/`strike`/`recover`/pozy (poprawki dopiero w D, po zrzutach „przed”). Nowe pola modułu:
```lua
COMBO_WINDOW = 1.5, -- seconds from the previous attack's start that keep a combo going (client only)
clipsByWeapon = {} :: { [string]: { ClipRef } }, -- F: clips of one weapon type, over the motion's clips
SFX = table.freeze({ ... }), -- E4: default sounds per motion
FLINCH = table.freeze({ seconds = 0.18, degrees = 5, critDegrees = 9, shoulder = 0.35 }), -- E3, looks only
TRAIL = table.freeze({ lifetime = 0.18, key = "trailStreak", base = 0.35, widthTip = 1, widthBase = 0.35 }), -- E1
```
(`base`: na jakiej części długości broni od dłoni zaczyna się smuga; dla `smash` 0,6, bo głowica: pole `trailBase` w `TRAIL.byMotion`, jeśli trzeba.)

**C2. `Logic/AttackPose.luau`:**
- `timing(name, interval?, step?)`: jak dziś, dla kroku `step` (domyślnie 1), z `hitAt = SERVER_HIT[name]` (gdy `interval` ściska ruch, `hitAt` ściska się razem: tak jak dziś, klient nie przekazuje `interval`, B), pole `hit` w `Timing` = wyliczony ułamek.
- `sample(name, t, interval?, from?, step?)`: fazy jak dziś (`Phase` bez zmian: `"windup" | "strike" | "recover" | "rest"`), w środku:
  - zamach: `smooth` od `from`/spoczynku do `windup`;
  - cios z `pass`: od `windup` do `pass` na `[windup, hitAt]` krzywą **`easeIn`** (`t²`: przyspiesza do kontaktu), od `pass` do `strike` na `[hitAt, windup + strike]` krzywą `easeOut` (hamuje po kontakcie); bez `pass`: jak dziś;
  - powrót z `follow`: od `strike` do `follow` przez `follow × recover` krzywą `easeOut`, potem `smooth` do spoczynku; bez `follow`: jak dziś.
  Ciągłość i waga bez zmian (testy S22 zostają).
- `stepCount(name): number` (`#clips` dla klipów, F; inaczej `#steps`) i `step(name, i): Step`.
- `nextStep(prev: { motion: MotionName, step: number, at: number }?, name: MotionName, now: number, count: number): number`: `1`, gdy `prev == nil`, inny ruch, `now − prev.at > COMBO_WINDOW` albo `count == 1`; inaczej `prev.step % count + 1`.
- `flinch(push: { x: number, z: number }, strength: number, t: number): Pose`: drgnięcie z kierunkiem (E3). `push` to kierunek pchnięcia w lokalnej ramie postaci (x w prawo, z do tyłu; przód postaci to −Z), znormalizowany; obwiednia `sin(π · t / seconds)`; talia: `x = push.z × deg` (odchyl do tyłu, gdy pchnięcie z przodu), `z = −push.x × deg` (przechył od strony ciosu, znak sprawdź testem i zrzutem); barki: `rShoulder`/`lShoulder` `x = −push.z × deg × shoulder` (ręce lekko w tył). `deg` = `FLINCH.degrees` albo `critDegrees` × `strength`.
- `Logic/MotionKeys.attack` (S110): dostaje argument kroku (`step?`), klucz `hit` = `SERVER_HIT`, `strikePeak` = koniec ciosu, `follow` = koniec `follow`; `MotionKeys.clip` dla klipów (F) bierze `hitTime`/prędkość z `ClipFit`. Nie liczysz klatek kontrolnych drugi raz w `AttackPose`.

**C3. Zasady §2 jako asercje (`tests/attackpose.spec.luau`, „§2 checks (S113)”):**
1. Zapowiedź: `windup ≥ 0.1` każdego kroku; dla `slash2h` i `smash` `windup ≥ 0.14` i `strike ≤ 0.12` (ciężar §2.4).
2. Trafienie: dla ruchów wręcz z `pass`: prędkość kątowa głównego stawu (`rShoulder`, dla kroku lewą ręką `lShoulder`; pole w danych nie jest potrzebne: bierz staw o największej zmianie między `windup` i `strike`) liczona różnicami co 1/240 s ma maksimum w `SERVER_HIT ± 0.03` (§2.2).
3. Wybrzmienie: dla kroków z `follow` znak zmiany głównej osi głównego stawu przez 0,04 s po końcu ciosu jest ten sam co w ciosie (ruch jedzie dalej), a poza `follow` różni się od `strike` o 3–20° (lekki overshoot, nie drugi zamach).
4. Bez „robota”: w ciosie i w powrocie nie ma dwóch kolejnych odcinków 1/60 s o identycznej niezerowej prędkości (`|Δv| > 1e-6`), czyli brak liniowej interpolacji.
5. Łuki: dla kroków wręcz pozycja dłoni liczona prostą kinematyką (barku i łokcia; długości ramienia 1,0 i przedramienia 1,0, wystarczy w ramie tułowia) w 8 próbkach ciosu odbiega od odcinka start–koniec co najmniej o 0,15 długości ręki w jednej próbce (ręka jedzie po łuku, nie po prostej).
6. Granice: każda poza (`windup`, `pass`, `strike`, `follow`) każdego kroku w `LIMITS`; łuk: lewa ręka trzyma we wszystkich krokach, prawa naciąga (test S22 dla kroków).

**E1. Smuga broni z teksturą.** `CombatFxController.weaponTrail` (721–758) przenieś do `Library.weaponTrail` jako jedną funkcję dla ataków i umiejętności:
