### A. Jedno miejsce blokad (`Logic/UseBlocks` + `src/server/UseGuards.luau`)

**A1. `src/shared/Logic/UseBlocks.luau` (nowy, czysty, ok. 90 linii).** Jedyne miejsce, które wie, **co** blokuje Eliksir Pełni i Płaszcz Przynęty, w jakiej kolejności się to sprawdza i jakim tekstem się to mówi. Kształt:

```lua
--!strict
-- Where the premium consumables refuse to work (DESIGN-17 §3, S122). One list per feature, checked in order; the
-- first active reason wins and its text is `<prefix>.block.<reason>`. WHO decides whether a reason is active lives
-- on the server (src/server/UseGuards.luau): every owning service registers one check in its Start. A reason with
-- no check yet is never active (PENDING: the session that builds the feature registers it and removes the entry).

export type Feature = "fullElixir" | "lure"
export type Reason =
	"dead" | "duel" | "arena" | "dungeon" | "pvpLock" | "city" | "underground" | "redZone" | "mounted"
	| "bloodMoon" | "tourney"

local UseBlocks = {}

UseBlocks.LISTS = table.freeze({
	-- DESIGN-17 §3: duel and arena (DuelService / ArenaService), boss dungeon, the 15 s PvP lock, Blood Moon, tournament
	fullElixir = table.freeze({ "dead", "duel", "arena", "dungeon", "pvpLock", "bloodMoon", "tourney" }),
	-- DESIGN-17 §3: city, caves and dungeons, red zone, arena, Blood Moon, on a mount, dead
	lure = table.freeze({ "dead", "city", "underground", "redZone", "arena", "bloodMoon", "mounted" }),
})
UseBlocks.PREFIX = table.freeze({ fullElixir = "fullElixir", lure = "lure" })
-- Reasons whose check a later session registers (no check = never blocks until then).
UseBlocks.PENDING = table.freeze({ bloodMoon = "S129", tourney = "S130" })
-- Reasons that have a check now and get one more later (documentation for S126/S127).
UseBlocks.LATER = table.freeze({ arena = "S126 ArenaService match, S127 arena server" })
-- Map biomes that count as "underground" for the lure (DESIGN-17 §3: cave / crypt / dungeon).
UseBlocks.UNDERGROUND = table.freeze({ cave = true, crypt = true, dungeon = true })

function UseBlocks.key(feature: Feature, reason: string): string -- "<prefix>.block.<reason>"
function UseBlocks.first(feature: Feature, active: { [string]: boolean }): string? -- first reason of the list that is active
function UseBlocks.reasons(): { string } -- every reason of every list, once, sorted (tests, /useblocks)

return UseBlocks
```

- `first` idzie po liście funkcji **w jej kolejności** i zwraca pierwszy powód z `active[reason] == true`; powód spoza listy funkcji jest ignorowany (np. `mounted` nie blokuje eliksiru). Kolejność ma znaczenie tylko dla komunikatu: śmierć zawsze pierwsza.
- Płaszcz **nie** ma `tourney` na liście (kontrakt go nie wymienia, a serwer turnieju i tak nie ma potworów); eliksir nie ma `city`, `underground`, `redZone`, `mounted` (leczenie w jaskini i czerwonej strefie przy potworach jest dozwolone, blokada PvP 15 s łapie walkę z graczem).
- Moduł nie zna serwisów ani graczy: to tylko dane i dwie funkcje. Test (Testy, blok 1) sprawdza listy z kontraktem.

**A2. `src/server/UseGuards.luau` (nowy, zwykły moduł jak `QuestEvents.luau`, ok. 90 linii, bez `game:GetService` i bez `require`, więc ładuje się też w Lune).** Rejestr warunków:

```lua
--!strict
-- Registry of the checks behind Logic/UseBlocks (S122). Not a service: owning services register in Start, the
-- features ask. No requires and no Roblox API, so tests load it in Lune.
--   register(reason, check, owner) -> unregister   several checks per reason are OR-ed (arena: Ristalle sand + match)
--   first(player, list) -> reason?                   the first reason of `list` with a true check (list order)
--   active(player, list) -> { reason }               every active reason (admin /useblocks)
--   owners(reason) -> { owner }                      who registered checks (admin, tests)
--   lastError(reason) -> string?                     the last error of a check of that reason
-- A check that errors counts as ACTIVE (fail closed): a broken check must never let the elixir work in PvP.

export type Check = (player: any) -> boolean
```

- `register` zwraca funkcję wyrejestrowania (testy; serwisy jej nie potrzebują). Ten sam `owner` dla tego samego powodu zastępuje swój poprzedni warunek (ponowny `Start` w Studio nie dubluje).
- `first` / `active` wołają warunki przez `pcall`; błąd = powód aktywny i `lastError[reason] = tostring(err)` (zasada „fail closed”, linia w DECYZJE). Powód bez warunku = nieaktywny.
- `UseGuards._reset()` tylko dla testów (czyści rejestr).
