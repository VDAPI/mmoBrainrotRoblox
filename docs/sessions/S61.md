### C. Pech wrogów (`misfortune`) i wspólny limit uniku

1. **`Logic/Damage.luau`** (wymaga `../Data/BuffCategories`):
   - `Params.miss: number?`: % szansy, że atakujący chybi (z `misfortune` na atakującym; w PvP już ×0,5); `Result.missed: boolean?`;
   - `Damage.avoidance(dodge: number, accuracy: number, miss: number?, block: number?): (number, number, number)`: szanse 0..1 na unik, chybienie i blok. Unik jak `dodgeChance` (:63, limit `dodgeCap`), chybienie `clamp(miss, 0, BuffCategories.caps.enemyMiss)`, blok `max(0, block)` (swój limit `blockCap` dopisze S64, który użyje tej samej funkcji). Suma najwyżej `(Combat.dodgeCap + Combat.avoidBonus) / 100` (nowe `avoidBonus = 10`, D1), przycinana w kolejności: unik zostaje, chybienie dostaje najwyżej resztę, blok to, co zostanie. Przykład: unik 30, pech 15 → 0,30 i 0,10;
   - `Damage.rollAvoid(dodge: number, miss: number, block: number, rng: Rng.Rng): ("dodge" | "miss" | "block")?`: **dokładnie jedno** losowanie `rng:next()`, jak dziś `rollHit` (:67): `r < d` unik, `r < d + m` chybienie, `r < d + m + b` blok, inaczej `nil`. Przy `miss = 0` wynik i ciąg losowań są identyczne jak dziś, więc testy z ziarnem i `balance.spec` się nie ruszają;
   - `computeDamage` (:87-91): przy `params.canDodge ~= false` woła `avoidance(defender.dodge or 0, attacker.accuracy or 0, params.miss)` i `rollAvoid(d, m, 0, rng)`; unik albo chybienie zwraca `{ amount = 0, crit = false, dodged = true, missed = outcome == "miss", element = element, lifesteal = 0 }`. `dodged = true` także przy chybieniu, więc każdy dzisiejszy odbiorca `dodged` (np. `Skills/Context.damage`, kontra) traktuje chybienie jak brak trafienia.
