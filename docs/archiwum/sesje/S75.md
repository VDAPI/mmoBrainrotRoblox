1. **Podstawa i pola `path`** w `Data/Skills/Warrior.luau` (A, ok. 10% czasu).
2. **`Data/Paths/Warrior.luau`**: 3 ścieżki, 60 węzłów, broń, `statPlan`, `wiki = false` (B, ok. 35%).
3. **Brakujące zachowania**, tylko jeśli ich nie ma (C, ok. 10%).
4. **Buildy wzorcowe i wagi przedmiotów** (D, ok. 10%).
5. **Tytuły i 105 kluczy tekstów na język** (E, ok. 15%).
6. **Testy** („Testy”, ok. 15%), potem dokumentacja i wiki (F, ok. 5%).

Nic z tej listy nie może zostać na później: A, B, C i E muszą wejść razem (inaczej Wojownik ma umiejętności bez węzłów albo węzły bez tekstów), a D i testy należą do zakresu. Gdy brakuje czasu, skracaj w tej kolejności: opisy węzłów do jednego zdania, komentarze w danych, opis w SESJE do listy punktów. Nigdy nie skracasz liczby węzłów, testu odbiorców haków, testów składania ani buildów wzorcowych.

**B2. Wspólne zasady węzłów** (2.2, 2.3, 3.2):
- Id `<pathId>_<nazwa>`, unikalne w grze; `kind` jak w kolumnie „Rodzaj” (`skill`, `passive`, `modify`, `aura`). Węzeł `skill` ma id `<pathId>_<skillId>`, `kind = "skill"`, `maxRank = 1`, `skill = "<skillId>"` i teksty swojej umiejętności (`nameKey = "skill.<skillId>.name"`, `descKey = "skill.<skillId>.desc"`), bez kluczy `path.*`. Pozostałe węzły: `nameKey = "path.<pathId>.<nazwa>.name"`, `descKey = "path.<pathId>.<nazwa>.desc"`.
- Wartości jak w umiejętnościach: `{ ranga 1, ranga max }` liniowo (np. `{ 4, 10 }` daje 4 / 7 / 10). **Środkowe rangi w tabelach ROZWOJ 10.3–10.5 są zaokrąglone** (Twierdza ×0,92 / 0,84 / 0,75 to 0,92 / 0,835 / 0,75): dane są liniowe, bez wyjątków. W tabelach niżej „← `pole = { a, b }`” znaczy: liczba z `node.values.pole` na randze węzła. Zapis według konwencji S57 B3 i wzoru `Data/Paths/Cleric` (S71): `passive` mapuje statystykę albo hak na nazwę pola (`passive = { hooks = { guardPerEnemy = "frontline" } }`); w `modify.bp` liczba to `{ ref = "<pole>" }` w `add`, `mul` i `values` (`mul = { cooldown = { ref = "fortress" } }`, `values = { share = { ref = "wallShare" } }`); liczbę dla efektu albo rodzaju przełomu podajesz przez nowe pole `values` umiejętności, na które wskazuje napis (S57 B3, S73 `ValueRef`). Nazwy nowych pól `values` nie powtarzają pól, które umiejętność już ma (lista niżej). Przykład:
  ```lua
  {
  	id = "standard_command", kind = "modify", maxRank = 3, glyph = "🗣",
  	nameKey = "path.standard.command.name", descKey = "path.standard.command.desc",
  	values = { command = { 1, 3 } },
  	modify = { skill = "battleCry", bp = {
  		values = { cmdAtk = { ref = "command" } },
  		allyEffect = { kind = "statBuff", duration = 20, stats = { physAtk = "cmdAtk", magAtk = "cmdAtk" }, pct = true,
  			target = "allies", category = "allyAttack" },
  	} },
  },
  ```
  Nowe pola `values` umiejętności i pełne kształty efektów są w tabelach B3–B5: `sacrificeGuard`, `vowShield`, `aegisShield`, `bastionGuard`, `bloodthirstMax`, `furyRestore`, `cmdAtk`, `cmdVigor`, `inspireCrit`, `rallyHeal`, `oathGuard`. `duration = 1.5` w efektach kręgu sztandaru jest umowne (S74: krąg nakłada impulsy). Gdy konwencja S57 nie sięga potrzebnego miejsca, rozszerz `Paths.skillMods` jedną ogólną regułą tak jak S71 (przypadek w `paths.spec`, linia w DECYZJE).
- Rzędy 3, 6 i 9 mają `choice = true` i po dwa węzły; rząd 8 jeden węzeł `skill` (zwieńczenie), rząd 11 jeden węzeł `modify` z `maxRank = 2`.
- `dipScale` zostaw domyślne (`DIP_SCALE = 1/3`): w rzędach 1–2 efekty drużynowe mają tylko Osłona (`guardian_cover`) i Głos Dowódcy (`standard_command`).
- `node.weapon` ma tylko Blok: `{ offhand = { "shield" } }` (ważne w każdym rzędzie, 2.8).
- `glyph`: jeden znak jak w `Data/Skills`; węzeł `skill` bierze glyph swojej umiejętności, a pozostałe węzły ścieżki nie powtarzają glyphów jej umiejętności.
- Kategorie efektów biorą statystyki i tryb z `Data/BuffCategories` (S53): `allyAttack` `physAtk` + `magAtk` (%), `allyVigor` `armor` + `mres` (%), `allyCrit` `critChance` (pkt proc., bez `pct`), `allyGuard` redukcja obrażeń.
