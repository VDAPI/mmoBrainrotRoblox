**B3. `src/server/Skills/Companion.luau`** (nowy, ok. 150–200 linii, `--!strict`; nagłówek: „The Hunter's falcon (S77, ROZWOJ 11.5): one per player, a damage loop scheduled with task.delay and guarded by a token, so a stopped or replaced falcon never strikes again. Royal Falcon (keystone hook `royalFalcon`) stays until the fight is over.”). Stan w tabeli modułu `active: { [Player]: State }`:
```lua
type State = {
	token: number, -- bumped on every start; a scheduled tick with an old token returns at once
	ctx: Context.Ctx, -- the Falcon cast (effective def, rank, breakpoint behaviours)
	endsAt: number, -- os.clock() of the normal end (duration + falconBond seconds without the keystone)
	interval: number,
	calmSince: number?, -- Royal Falcon: when the hunter left combat
}
```
API (publiczne funkcje modułu):
- `Companion.start(ctx)`: odczyt haków przez `ctx.services.Combat.Hook(player, id)` (przedmioty i ścieżki); `royal = hook("royalFalcon") > 0`; `duration = ctx.scaled(ctx.skill.duration) + (if royal then 0 else hook("falconBond"))`; `interval = math.max(rules.minInterval, ctx.skill.interval × (1 − hook("falconInterval") / 100))`; nowy `token` (licznik modułu), wpis w `active` (zastępuje poprzedni: ponowny rzut nie dubluje pętli; ptak u klienta zostaje, bo klucz to id rzucającego). `ctx.fx({ t = ctx.caster.id, d = keep })` (zdarzenie bez `v` = elementy `impact` z H1, w tym `falcon`), gdzie `keep = (ctx.skill.delay or 1) + interval + 1`. Pierwsze uderzenie `task.delay(ctx.skill.delay or 1, tick, player, token)`.
- `Companion.stop(player, silent: boolean?)`: `active[player] = nil` (token przestaje pasować, więc zaplanowany `tick` wraca od razu); bez `silent` `ctx.fx({ v = "falconEnd" })` (odlot u klientów). Wywołania: `ResourceService.Died`, `CharacterService.CharacterLeaving` i `Players.PlayerRemoving` w `SkillService.Start` (603–640; przy `PlayerRemoving` z `silent = true`, bo encji już nie ma), koniec czasu i koniec walki w `tick`.
- `Companion.dive(player, target)`: nurkowanie Królewskiego Sokoła (B5).
- `Companion.active(player): boolean` (dla nurkowania i ewentualnych testów ręcznych przez admina; nic więcej z zewnątrz nie czyta stanu).

**`tick(player, token)`** (lokalna; kolejność ma znaczenie):
1. `local state = active[player]`; `if not state or state.token ~= token then return end` (zatrzymany albo zastąpiony sokół nie robi nic i niczego nie planuje).
2. Rzucający w grze: `player.Parent`, `ctx.root.Parent` i `not ctx.services.Resource.IsDead(player)` (jak `cast`); inaczej `Companion.stop(player)` i koniec.
3. Koniec: `royal` czytany **w każdym tiku** (`hook("royalFalcon") > 0`; węzeł mógł zostać zwrócony). Bez `royal`: `os.clock() >= state.endsAt` → `stop`. Z `royal`: gdy `ctx.services.Resource.InCombat(player)`, `state.calmSince = nil`, inaczej `state.calmSince = state.calmSince or now`; koniec, gdy `now >= state.endsAt` **i** `state.calmSince ~= nil and now − state.calmSince >= rules.linger` (Królewski Sokół nigdy nie odlatuje wcześniej niż zwykły, a po walce zostaje jeszcze 5 s; `InCombat` sam gaśnie 5 s po ostatnim ciosie).
4. Cel (B4). Strefa zielona (`ctx.services.Zone.GetPvpZone(player) == "green"`) albo brak celu: `ctx.fx({ v = "falconCircle", d = keep })`. Inaczej `strike(state, target, pct, false)`, gdzie `pct = ctx.value("dmg") × (1 + hook("falconDamage") / 100)`.
5. Zawsze na końcu, tylko gdy stan wciąż ten sam (`active[player] == state`): `task.delay(state.interval, tick, player, token)`. W całej pętli istnieje najwyżej jedno zaplanowane wywołanie na gracza.

**`strike(state, target, pct, dive)`** (lokalna):
- `local result = ctx.damage(target, pct, { consumeShot = false, primary = true, noProc = true })`: `consumeShot = false` (uderzenie sokoła nie zużywa `guaranteedCrit` z Kamuflażu ani Namierzenia 10B ani `nextShot` z Odskoku), `primary = true` (10B `splash` działa przez `onHit`), `noProc = true` (S63: sokół to nie broń, nie wyzwala cech przedmiotów przy trafieniu ani Słabego Punktu, E1). Jeśli `Context.damage` z S63/S76 nie przekazuje `noProc` do `DealDamage`, dopisz to.
- Przy trafieniu (`result and not result.dodged`): `ctx.applyEffects(target, "enemy")` (5B: spowolnienie `enemySlow`) i przy `royal` `ctx.services.Combat.Spot(player, target)` (E2: Królewski Sokół nakłada Oznaczenie).
- Gdy `result ~= nil` (trafienie albo unik) i cel to gracz (`target.kind == "player"`): `ctx.services.StatusEffect.Remove(target, "camouflage")` (11.5: w PvP uderzenie zdejmuje Kamuflaż; przy uniku też, bo ptak i tak go wypatrzył).
- Zdarzenie: `ctx.fx({ v = if dive then "falconDive" else "falconStrike", t = target.id, d = keep })`. Obrażenia lądują od razu (ptak u klienta leci ok. 0,25 s; to ta sama tolerancja co dziś przy pociskach).

**B4. Cel sokoła** (lokalna `pickTarget(state)`; ROZWOJ 11.5: „obecny cel Łowcy, czytany w każdym uderzeniu, a bez celu najbliższy wróg w 30 st.”):

2. Inaczej najbliższy potwór z `ctx.services.Entity.QueryMonsters(ctx.root.Position, ctx.skill.radius)`, dla którego `ctx.isEnemy(entity)` **i** jego tabela zagrożenia (`entity.monster.threat`) ma Łowcę albo członka jego drużyny (`ctx.services.Party.Members(player)`, z samym graczem). Remis odległości rozstrzyga `entity.id`. Sokół nie zaczyna więc nowych walk sam: bez tego warunku Łowca stojący w polu z Królewskim Sokołem biłby każdego przechodzącego potwora (farma AFK) i ściągał grupy na drużynę. Zapisz to w DECYZJE.
3. Bez celu: `nil` (krąży).

**B5. Nurkowanie Królewskiego Sokoła** (ROZWOJ 11.5: „Znak Łowcy wysyła go w nurkowanie na oznaczony cel: 150% obrażeń i ogłuszenie 1 s (`notBoss`)”, PvP: „nurkowanie nie ogłusza graczy”):

Nurkowanie nie przesuwa harmonogramu uderzeń.

**B6. Sprzątanie i wycieki** (ryzyko sesji). Sprawdź w kodzie przed commitem i opisz w komentarzu nagłówka:

### D. Namierzenie: efekt `sighted` i dodatek krytyka

**D1. Efekt.** Rodzaj `sighted` (A1) na celu, ze źródłem = Łowca: tylko jego trafienia w ten cel mają dodatek do szansy na krytyk i do obrażeń krytycznych (ROZWOJ 11.3: „`own`, nie dubluje Znaku”). W danych (F1): `{ kind = "sighted", duration = 10, stats = { critChance = "crit", critDmg = "critDmg" } }`, bez kategorii (to nie efekt drużynowy; test kategorii S53 nie wymaga jej dla rodzajów spoza listy, a jeśli wymaga, dopisz `sighted` do rodzajów bez kategorii z komentarzem). `Context.applyEffect` już rozwiązuje `stats` na liczby (322–350), więc efekt niesie `stats = { critChance = 12…20, critDmg = 15…30 }`.
- `StatusEffectService`: `sighted` w `DEBUFFS` (oczyszczenie w PvP je zdejmuje); źródło statystyk z efektów dalej czyta tylko `statBuff` (sprawdź; `sighted` nie może zmienić statystyk nosiciela). Nowa `StatusEffectService.FromSource(entity, kind, player): Effect?` (aktywny efekt rodzaju ze `source == player`, najdłuższy przy kilku); `HasFrom` z S76 przepisz na `FromSource(...) ~= nil`.
- Dwóch Łowców na jednym celu: osobne wpisy (klucz S53 zawiera źródło), każdy liczy tylko swój.

**D2. `Logic/Damage.luau`:** `Params` dostaje `critAdd: number?` (punkty procentowe szansy) i `critDmgAdd: number?` (punkty procentowe obrażeń krytycznych). Nowa czysta funkcja i jej użycie w `computeDamage` (103–108):
```lua
-- S77: crit chance (%) of one hit. `critAdd` (Draw a Bead) raises the attacker's chance up to the critChance cap
-- (Data/Stats) and never lowers it; the level advantage (gapCrit) comes on top, as before.
function Damage.critChance(attacker: Attacker, params: Params, gapCrit: number): number
```
`base = attacker.critChance`; `withSight = math.max(base, math.min(cap, base + (params.critAdd or 0)))`, gdzie `cap = Stats.get("critChance").cap` (60); wynik `math.clamp(withSight + gapCrit, 0, 100)`. W `computeDamage`: `local critChance = Damage.critChance(attacker, params, gapCrit) / 100`, a mnożnik krytyka `math.max(1, (attacker.critDmg + (params.critDmgAdd or 0)) / 100)`. Bez `critAdd` i `critDmgAdd` wynik jest bit w bit dzisiejszy (ta sama kolejność losowań `rng`).

**D3. `CombatService.DealDamage`:** po bloku `guaranteedCrit` / `nextShot` (412–422), przed rozgałęzieniem na potwora i gracza: `local sight = StatusEffectService.FromSource(targetEntity, "sighted", player)`; przy `sight and sight.stats`: `params.critAdd = sight.stats.critChance`, `params.critDmgAdd = sight.stats.critDmg` (komentarz `-- S77: Draw a Bead, only the caster's hits (ROZWOJ 11.3).`). Działa dla ataków podstawowych, umiejętności i uderzeń sokoła tego Łowcy; tyknięcia trucizny nie przechodzą przez `DealDamage` i nie mają krytyka.

**D4. 10B Namierzenia** (`selfEffect` `guaranteedCrit` 5 s, `category = "own"`): działa przez istniejący blok `guaranteedCrit` w `DealDamage`; nic do dopisania poza danymi.
