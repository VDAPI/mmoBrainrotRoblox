### B. Reguły planera w TS (`wiki/src/lib/skills.ts`, od nowa)

Czyste funkcje bez importu `src/data` (planer dostaje dane w propsach, test podaje pliki). Wiki nie powtarza wzorów gry: punkty, poziomy rang, opisy i warianty biorą się z eksportu; TS tylko porównuje liczby, a reguły ścieżek odtwarza w kolejności `Logic/Paths.canBuy`. Stary kod S41/S56 usuń w całości.

1. **Typy:**
   ```ts
   export interface RuleSkill { id: string; order: number; unlock: number; maxLevel: number; passive: boolean;
     rankLevels: number[]; hasB: { 5: boolean; 10: boolean }; path?: string }
   export interface RuleNode { id: string; kind: string; maxRank: number; skill?: string; skillB?: number[] }
   export interface RuleRow { row: number; level: number; required: number; kind: string; choice: boolean; nodes: RuleNode[] }
   export interface RulePath { id: string; class: string; order: number; rows: RuleRow[] }
   export interface PathRules { maxLevel: number; pathPointsByLevel: number[]; mainPathLevel: number; dipRows: number }
   /** One build set: like the game save (path.main, path.nodes, path.bp with keys "<skillId>:5"). */
   export interface PlanBuild { level: number; main: string | null; nodes: Record<string, number>; bp: Record<string, "a" | "b"> }
   ```
   Typy `SkillPath`, `SkillPathVectors` i reszta przychodzą z wygenerowanego `src/data/types.ts`; `RulePath` ma do nich pasować bez kopiowania.
2. **Podstawa:** `rankAt(skill, level)` (liczba `rankLevels` ≤ level), `nextRankLevel(skill, level)` (albo `null`), `bpOpen(skill, rank, level)` (level ≥ `rankLevels[rank − 1]`), `choiceAt(build, skillId, rank)` (`"b"` tylko przy wpisie `"b"`, inaczej `"a"`), `variantKey(build, skill, rank)` (litera dla 5 tylko od rangi 5, dla 10 tylko od rangi 10; `"aa"` = sama ranga, inny klucz = `variants[key]`), `setChoice(build, skillId, rank, option)` (nowy obiekt; `"a"` usuwa wpis, bo w grze brak wpisu działa jak A).
3. **Ścieżki (lustro gry):** `pointsAt(rules, level)` (z `pathPointsByLevel`), `spent(paths, build)` (jak gra: tylko znane węzły), `free(paths, rules, build)`, `pathPoints(path, build)`, `canBuy(paths, rules, build, nodeId): BuyResult` i `canRefund(paths, rules, build, nodeId): RefundResult` **z tymi samymi kluczami powodów (`paths.error.*`), kolejnością sprawdzeń i ewentualnym `detail` co `Logic/Paths`** (przepisz je, czytając kod gry linijka po linijce; listę kluczy wystaw jako `export const BUY_ERRORS = ["paths.error.unknown", …] as const` i `REFUND_ERRORS`; teksty wiki `planner.why.<ostatni człon klucza>`), `achievable(paths, rules, build)` (dokładnie algorytm z A4, ta sama kolejność), `validate(paths, rules, build)` → `{ ok, over, unreached: string[] }` (`over` = punkty ponad poziom, `unreached` = węzły, których odtworzenie nie osiąga), `setMain(paths, rules, build, pathId | null)` (jak `ChooseMainPath` w grze: zwraca rangi rzędów > `dipRows` starej ścieżki głównej; `null` zdejmuje ścieżkę główną i te same rangi), `canSetMain(rules, build)` (level ≥ `mainPathLevel`).
4. **Model widoku** (Svelte tylko go rysuje, więc logikę zakładki ścieżki testujesz bez przeglądarki): `baseView(skills, build)` → wiersze `{ id, rank, max, next, bp: [{ rank, level, open, choice, hasB }] }`; `pathView(path, paths, rules, build)` → `{ isMain, points, rows: [{ row, level, required, have, open, reason: "level" | "need" | "main" | null, nodes: [{ id, rank, max, state, invalid, buy, refund, dip }] }] }`, gdzie `state` to `"locked" | "available" | "partial" | "max"` jak w `SkillNode`, `invalid` = węzeł z rangą, którego `achievable` nie osiąga na tym poziomie, `dip` = węzeł z `dipScale` w ścieżce, która nie jest główna.
5. **Kod buildu v2.** Format (wielkość liter i spacje bez znaczenia, tylko znaki bezpieczne w adresie):
   `2<KLASA><poziom>.<główna>.<przełomy>.<ścieżka order 1>.<ścieżka order 2>[.<ścieżka order 3>]`
   - `2` = wersja. Kod, który nie zaczyna się od `2` i litery (każdy kod v1, np. `MAGE34-a035030-0000000`), daje błąd `old`.
   - `<KLASA>` = id klasy wielkimi literami (inna klasa: `class`), `<poziom>` 1…`maxLevel` (`level`).
   - `<główna>` = `order` opublikowanej ścieżki głównej albo `0` (`main`, gdy takiej opublikowanej ścieżki nie ma).
   - `<przełomy>` = po jednym znaku `0`–`3` na każdą aktywną umiejętność **podstawy** (bez `path`) w kolejności `order`, także bez B (bit 1 = B na 5., bit 2 = B na 10.; bit B, którego nie ma: `bp`).
   - Segmenty ścieżek są **pozycyjne**: k-ty segment należy do ścieżki z `order == k`, a ścieżka, której planer nie zna (nieopublikowana), ma segment pusty (niepusty: `length`). Po jednej cyfrze na węzeł (rzędy rosnąco, węzły w kolejności rzędu): zwykły węzeł `0`–`maxRank`; węzeł `skill` `0` (niekupiony) albo `1`–`4` (kupiony, `1` + bity przełomów jego umiejętności jak w `<przełomy>`, dozwolone według `skillB`); zła cyfra: `rank`, bit B, którego nie ma: `bp`.
   - Dzięki temu publikacja kolejnej ścieżki (w dowolnej kolejności) i dodanie B dawnej umiejętności nie zmieniają znaczenia starych kodów v2: dochodzi tylko nowy segment albo nowy dozwolony bit.
   - Postać kanoniczna: segment `<główna>` jest zawsze (także `0`); w kolejnych segmentach końcowe zera są ucięte, puste segmenty na końcu pominięte, a pusty segment w środku znaczy „same zera” (np. `2MAGE34.0`, `2MAGE34.0.1`, `2MAGE60.1..1333`). Dekoder dopełnia zerami i przyjmuje też brak segmentów po poziomie; za długi segment albo niepusty segment ponad największy `order` opublikowanej ścieżki: `length`; pusty tekst: `empty`. `decodeBuild` nigdy nie rzuca wyjątku i zwraca `{ ok: true, build } | { ok: false, error }`. `decodeBuild(encodeBuild(b)) == b` dla każdego poprawnego `b`.
   - Kod nie sprawdza zasad gry (od tego jest `validate`): zdekodowany build może być nieosiągalny i planer to pokazuje.
6. **Propsy wyspy** (`plannerData(c, lang)` w `wiki/src/lib/classes.ts`): `skills` = umiejętności klasy z eksportu (podstawa i opublikowane ścieżki) w jednym języku (nazwa, glif, kolor z `skillColor`, zasób, zasięg, `elementNote`, rangi z wariantami, przełomy z tekstami A/B i poziomem), `paths` = opublikowane ścieżki klasy (nazwa, opis, rola, nazwy broni przez `baseName`, rzędy, węzły z nazwą, glifem, `dipScale`, opisami rang i `dipDesc` w tym języku, `skill`, `modify`, `weapon`), `rules` (`PathRules` z `maxLevel`, plus `pathPointsEvery` i `rows` do tekstu „Ścieżki wkrótce”), `labels` (klucze `planner.*` bez przedrostka), `scroll` (nazwa i link `scroll_skillreset`, w grze Zwój Nowej Ścieżki). Wyspa nie importuje JSON z `src/data`.
