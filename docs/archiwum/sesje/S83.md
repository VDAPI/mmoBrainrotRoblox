### E. `Data/SkillCurves` i węzły w `Skills.valueAt` (plan balansu 2.2, ROZWOJ 2.5)

1. **`src/shared/Data/SkillCurves.luau` (nowy):**
   ```lua
   --!strict
   -- Per-skill value knots for the balance sessions (balance plan 2.2, ROZWOJ 2.5). Empty until S89.
   -- knots[skillId][field] = { [rank] = value }. Only for a `values` field that is a { rank 1, rank max } pair,
   -- ranks 2 .. maxLevel - 1. Logic/Skills.valueAt interpolates linearly in rank:
   --   (1, pair[1]) -> knots in rank order -> (maxLevel, pair[2]).
   -- Band of a knot = band of Skills.rankLevel(skill, rank): <= 20 -> 1-20 (S91), 21-45, 46-70, 71-100.
   -- Changing rank max without moving the ranks reached at <= 20: first add a knot at the last rank with
   -- rankLevel <= 20 equal to today's value there, then change pair[2] (or add knots at the last ranks
   -- reachable at 45 and 70). Never add a third element to the pair. Not read by tools/WikiData.
   export type Knots = { [string]: { [string]: { [number]: number } } }
   return table.freeze({ knots = table.freeze({}) :: Knots })
   ```
   Zamrożenie ma być głębokie (późniejsze wpisy też w `table.freeze`), jak w innych modułach danych.
2. **`Logic/Skills.luau`:**
   - `Skills.interpolate(points: { { number } }, rank: number): number`: czysta, punkty `{ ranga, wartość }` posortowane po randze, liniowo między sąsiednimi, poza zakresem przycięte do skrajnych;
   - `Skills.valueAt(skill, field, rank)`: gdy `skill.values[field]` to para i `SkillCurves.knots[skill.id]` ma węzły dla `field`, buduje punkty `(1, para[1])`, węzły, `(maxLevel, para[2])` i woła `interpolate`; **bez węzłów zwraca dokładnie `Skills.scaled(skill, value, rank)`** (ta sama arytmetyka, więc wiki i fixture zostają co do bitu); liczba przechodzi bez zmian jak dziś;
   - w `effective` (po S55) `def.values[field] = Skills.scaled(skill, def.values[field], rank) + amount` przechodzi na `def.values[field] = Skills.valueAt(def, field, rank) + amount`, a `def.values.jumps = Skills.scaled(skill, def.values.jumps, rank) + jumps` na `Skills.valueAt(def, "jumps", rank) + jumps`. Czytasz `def` (klon z tym samym `id` i `maxLevel`), nie bazowe `skill`: wcześniejsze źródło (przełom 5, węzeł) mogło już zmienić tę wartość na liczbę, a liczba przechodzi przez `valueAt` bez zmian, tak jak dziś przez `scaled`.    - `Skills.healAmount` (S69): `Skills.scaled(def, hpField, rank)` i `Skills.scaled(def, magField, rank)` przechodzą na `Skills.valueAt(def, prefix .. "Hp", rank)` i `Skills.valueAt(def, prefix .. "Mag", rank)` (brak pola daje 0, tak jak `scaled(def, nil, rank)`);
   - inne miejsca z S55–S82 znajdziesz przez `grep -rn "scaled(" src tools tests`: każde wywołanie, którego wartość pochodzi z `values` (wprost albo przez zmienną), przepinasz tak samo. Koszt, odnowienie i czasy trwania (`cost`, `cooldown`, `duration`, `effect.duration`) zostają na `scaled` (węzły dotyczą tylko `values`).

### G. Model bossa

1. **Harmonogram.** `Balance.BOSS_GLOBAL_GAP = 2.2` (lustro `Boss.luau` 65; osłona tekstem w I5) i `Balance.bossCadence(def, phase, opts?)` → `{ perMinute = { [attackId]: number }, rateShare = { [attackId]: number }, casting: number }`: krok `opts.step` (0,05 s), czas `opts.seconds` (600), `opts.globalStart` (4), `opts.firstUse` (5, średnia z 3 + U(0, 4)), `opts.gap`; w każdym kroku, gdy `t ≥ nextGlobal`, wybór ataku: domyślnie pierwszy gotowy w kolejności listy (dzisiejszy `Boss.Step`), a przy `opts.pick(ready: { Attack }, t, state) → Attack?` wybór należy do niego (tu S87 podłączy `Logic/BossSchedule`); `state = { nextAttack = { [attackId]: number }, nextGlobal = number, phase = number }`, bo reguła S87 (największe `(t − nextAttack) / cooldown`) potrzebuje `nextAttack`. `rateShare` = rzuty na minutę / (60 / odnowienie); `casting` = suma zamachów / czas.
2. **Walka.** `Balance.bossFight(bossId, team: { Player }, opts?)` → `{ hp, seconds, phases = { { share, seconds, shieldSeconds, casts, tankDps, raidDps } }, enraged: boolean, enrageAt: number?, biggestHit = { [classId]: number }, tankDps, potionHps, hazards = { … } }`:
   - HP i obrona jak w `Balance.boss` (`kindFor`: `BossScaling.hpMultiplier(n) × def.hpMul`), DPS drużyny z `BOSS_UPTIME`; udziały HP faz z `def.phases` (dziś 30 / 35 / 35%);
   - obrażenia **na atak**: `ability.damageKind or def.damageKind` (CombatService 726–727) przeciw obronie celu, × `Combat.randomMax` tylko dla największego ciosu; cele: `threat` i `nearest` → tank (pierwszy gracz drużyny), `self` z kształtem `circle` → gracze walczący wręcz (Łowca i Mag stoją dalej), `self` z kształtem `ring` (bezpieczny środek `inner`: `deathRing`, `inferno`, `glacialRing`) → gracze walczący z dystansu, bo wręcz stoją w środku, `random` → `min(count, n)` celów, każdy gracz z udziałem `min(count, n) / n`, `all` → wszyscy; ataki z czerwoną strefą trafiają z udziałem `opts.specialHit` (domyślnie `Balance.SPECIAL_HIT` = 0,5, konwencja S32 i `FightSim`; raport też 1 = nikt nie schodzi ze strefy);
   - atak podstawowy bossa w tank co `attackInterval / haste[faza]` przez czas bez rzucania (`1 − casting`); wściekłość: po `enrageAfter` atak × `enrageDamage` (dotyczy też ataków specjalnych);
   - tarcze: dla `summons` z `shield` fala `count + SUMMON_PER_PLAYER × (n − 1)` pomocników na `summon.level` (Grimrok w drużynie 5: 18); boss nietykalny i nie atakuje, dopóki żyją; czas fali = HP pomocników / DPS drużyny przeciw nim, ich obrażenia jak grupa na tanku; przywołania z `every` dodają fale co `every` s fazy;
   - `biggestHit[classId]` = największy pojedynczy cios / maks. HP klasy (metryka S32: Mag na L20 do 70%); `tankDps` = obrażenia na sekundę w tanka (mianownik T-SK6 dla S85–S86); `potionHps = Balance.potionHps(L)`.
3. **Przyspieszenie.** `def.haste[faza]` dzieli odstęp ataku podstawowego, nie odnowienia ataków specjalnych (`applySpeed` 132–137): tak też w modelu.
4. **Vaelgrath faza 2.** Lot trwa `FLIGHT_SECONDS` i boss jest wtedy nietykalny; sprawdź w `vaelgrath.luau`, czy w locie atakuje, i odwzoruj (dolicz czas fazy).
