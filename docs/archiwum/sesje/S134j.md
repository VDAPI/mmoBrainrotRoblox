### A. Logika `src/shared/Logic/Reroll.luau` (czysta)

1. **Stan na przedmiocie:** `ItemInstance.rr: { i: number, n: number }?` (`Types.luau`, komentarz `-- S134j: bonus reroll state: i = index in bonuses of the only rerollable line (set by the first reroll), n = rerolls done (cost growth)`). Brak pola = przedmiot nigdy nieprzemieniany. **Bez migracji** (`AccountSchema.CURRENT` bez zmian; pole opcjonalne). Odczyt tylko przez `Reroll.state(item) -> { line: number?, n: number }` z ochroną typów: `n` całkowite ≥ 0 (śmieci → 0), `i` całkowite w zakresie `bonuses` i wskazujące linię, którą wolno przemieniać, inaczej `line = nil` (wybór znów otwarty, licznik zostaje; linia w DECYZJE: „indeks spoza zakresu po zmianie danych otwiera wybór, nie kasuje kosztu”).
2. `Reroll.eligible(item) -> (boolean, string?)`: przedmiot z `Items.get(item.id).category == "equipment"`, bez `def.fixedBonuses` (`smith.reroll.error.fixed`), z co najmniej jedną linią, którą wolno przemieniać (`smith.reroll.error.noLines`; Zwykły, wytworzony u kowala). Bez warunku rzadkości (Unikat, Heroiczny, Legendarny i **Mityczny** tak samo).
3. `Reroll.canLine(item, index) -> (boolean, string?)`: linia istnieje, jest zwykła (`Bonuses.get(stat).tier == "regular"`; linie `leg_*` / `myth_*` nieprzeliczonych jeszcze przedmiotów z poczty / aukcji i nieznane id odrzucone — `smith.reroll.error.notRegular`), a gdy `state.line` jest ustawione, `index == state.line` (`smith.reroll.error.lockedOther`). Efekty `fx`, baza, cecha i `up` nigdy nie są „linią”.
4. `Reroll.pool(item, index, classId) -> { [string]: number }`: wagi `ItemRoll.poolWeights(item.id, classFor(item, classId))` (A, Kontekst: klasa postaci, jeśli przedmiot do niej pasuje), **minus** statystyki pozostałych linii przedmiotu i minus markery, z których pochodzą (linia `vs_wolf` wyklucza marker `vs_family`, jak przy upadku: jeden wariant markera na przedmiot); **obecna statystyka wybranej linii zostaje w puli** (może wyjść ta sama statystyka z nową wartością). Pusta pula (teoretycznie) → `smith.reroll.error.empty`.
5. `Reroll.roll(item, index, classId, rng) -> Types.Bonus`: `rng:weighted(pool)`, marker rozwinięty przez `ItemRoll.expandParam(id, rng, nil)` (rodzina losowa; linia w DECYZJE), wartość `ItemRoll.rollBonusValue(id, item.ilvl, item.rarity, rng:next())`. Bez mutacji przedmiotu.
6. `Reroll.apply(item, index, line)`: podmienia `bonuses[index]`, ustawia `rr = { i = index, n = n + 1 }` (pierwsza przemiana zamyka wybór na `index`). Kolejność linii w `bonuses` bez zmian (opis sortuje je grupami S134g).
7. `Reroll.preview(item, index, classId) -> { { stat: string, chance: number, min: number, max: number, marker: boolean } }`: szansa = waga / suma (markery jako jedna pozycja „przeciw rodzinie / klasie” z zakresem), zakres `ItemRoll.bonusRange(id, ilvl, rarity) × ItemRoll.lineMultiplier(item, id)`, kolejność wg `TooltipModel.STAT_GROUPS` (S134g; bez tej listy — kolejność puli). Suma szans = 1.
8. `Reroll.cost(item) -> { gold: number, materials: { { id: string, n: number } } }` z `Config.Reroll` (start, model decyduje w F):
   - `essence` według rzadkości: Unikat `{ essence_dust, 4 }`, Heroiczny `{ essence_shard, 2 }`, Legendarny `{ essence_crystal, 1 }`, Mityczny `{ essence_crystal, 2 }`;
   - `goldMul` 3: złoto bazowe `ilvl × Upgrade.goldPerIlvl(ilvl) × goldMul` (ta sama krzywa złota co ulepszanie, bez nowej krzywej);
   - wzrost: mnożnik `min(1 + growth × n, growthCap)`, `growth` 0,25, `growthCap` 4 (od 13. próby koszt stały ×4), złoto `floor(… + 0,5)`, esencja `ceil(base × mnożnik)`.
   - `Reroll.costWithStone(item)`: ten sam koszt bez materiałów (Kamień płaci esencję), złoto bez zmian.
