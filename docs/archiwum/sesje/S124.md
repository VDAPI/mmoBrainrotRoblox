- `Leaderboard.LEVEL_BASE = 1e10`, `Leaderboard.FRAC_BASE = 1e9`.
- `Leaderboard.levelScore(level: number, exp: number, reachedAt: number?, now: number): number`: poziom przycięty do `1..Config.MaxLevel`; dla poziomu < `MaxLevel`: `level × LEVEL_BASE + clamp(floor(exp / Exp.expToNext(level) × FRAC_BASE), 0, FRAC_BASE − 1)`; dla `MaxLevel`: `MaxLevel × LEVEL_BASE + (LEVEL_BASE − 1 − (reachedAt or now))` (kto pierwszy, ten wyżej; brak `reachedAt` traktuje jak „teraz”, choć serwer zawsze je ustawia, C4). Zawsze liczba całkowita, `< 2^53` (komentarz: OrderedDataStore przyjmuje tylko liczby całkowite; `1.01e12` mieści się z zapasem).
- `Leaderboard.decodeLevel(score: number): (number, number?)` → `(level, frac 0..1 albo nil na MaxLevel)`; dla okna („57 (43%)”) i planszy.
- `Leaderboard.SCORERS: { [string]: (character: any, now: number) -> number? }` z jednym wpisem `level = function(c, now) return levelScore(c.level, c.exp, c.reached100At, now) end`. **Scorer dostaje tylko postać** (komentarz: „no account, no purchases: DESIGN-17 §0.2, tests/paywall.spec”). S125+ dopisują swoje.

**B2. Id tablic i części.**
- `Leaderboard.PARTS: { [string]: (ctx: { now: number }) -> string }` z jednym wpisem `week = function(ctx) return tostring(Time.weekNumber(ctx.now)) end` (tydzień S98; S125 go użyje, S124 tylko testuje).
- `Leaderboard.instanceId(def, parts: { string }?): string` = `def.id` albo `def.id .. "_" .. table.concat(parts, "_")`; liczba części musi się zgadzać z `#def.parts` (inaczej `error`).
- `Leaderboard.resolve(instanceId: string): (BoardDef?, { string }?)`: najpierw dokładne `byId`, potem najdłuższy prefiks `def.id .. "_"` dla definicji z `parts` i podział reszty na tyle kawałków, ile `#def.parts`: pierwsze `#parts − 1` kawałków to `[%w]+` oddzielone `_`, **ostatni kawałek bierze całą resztę** (może zawierać `_`, np. przedział areny `40_59` w `arena_202611_40_59`, S126), żaden pusty. Dopisz też `PARTS.season` (`Time.monthKey` z S121, "YYYYMM") obok `PARTS.week`. Nieznane → `nil`. Tego używa remote (C6) i komenda admina: klient podaje tylko string.
- `Leaderboard.boardFor(tab: TabDef, filterValue: string?): string?`: dla `filter = "class"` tablica z `def.class == filterValue` (albo bez klasy, gdy `filterValue == nil`).
- `Leaderboard.entryKey(userId: number, slot: number | string): string` = `"<userId>_<slot>"`; `Leaderboard.parseKey(key): (number?, string?)` (userId, slot; `nil` dla kluczy gildii `"g_…"`).

**B3. Wykluczenia.** `Leaderboard.excluded(userId: number, character: any, adminIds: { number }, cfg): boolean` = `cfg.excludeAdmins and table.find(adminIds, userId)` albo `character.lbHidden == true`. Osobno `Leaderboard.eligible(character, cfg): boolean` = `character.level >= cfg.minLevel`. W Studio wszyscy są adminami dla komend (`AdminService.IsAdmin`), ale wykluczenie czyta **tylko** `Config.AdminUserIds` (pustą w Studio), więc w Studio ranking się wypełnia (komentarz).

**B4. Atrapa tablicy w pamięci** (używa jej `Stores` jako atrapy OrderedDataStore i SortedMap; testowalna w Lune):
- `Leaderboard.memoryBoard(): MemoryBoard` z metodami `set(key, score, value?, expiresAt?)`, `update(key, fn: (old: { score: number, value: any }?) -> (number?, any?), expiresAt?, now)` (zwrot `nil` z `fn` = bez zmian), `remove(key)`, `get(key, now): { score, value }?`, `top(n, now): { { key, score, value } }` (malejąco po wyniku, przy remisie rosnąco po kluczu, pomija wygasłe), `size(now)`.
- Kolejność remisów deterministyczna (test), wygasanie liczone od `now` z argumentu.

**B5. Dławienie zapisów i paczki przyrostów.**
- `Leaderboard.newThrottle(): Throttle` = `{ last: { [string]: number }, pending: { [string]: Pending } }` z `Pending = { board: string, key: string, score: number?, delta: number?, meta: Meta? }`.
- `Leaderboard.queue(t, instanceId, key, entry, now, gap): boolean`: zapisuje oczekujący wpis (wynik nadpisuje poprzedni, `delta` się **sumuje**, `meta` nadpisuje), zwraca `true`, gdy wolno zapisać od razu (`now − last >= gap`).
- `Leaderboard.due(t, now, gap, force?): { Pending }`: wpisy, których czas minął (albo wszystkie przy `force`, przy wyjściu i zamykaniu), z ustawieniem `last` i usunięciem z `pending`. Klucz dławienia = `instanceId .. "|" .. key` (każda tablica osobno, jak w kontrakcie „raz na 60 s na klucz”).

**B6. Cache i pozycja gracza.**
- `export type Meta = { n: string, c: string?, g: string?, l: number?, u: number?, t: number }` (imię, klasa, tag gildii, poziom, userId, czas zapisu).
- `export type Row = { r: number, n: string, c: string?, g: string?, l: number?, p: number?, s: number, at: number?, mine: boolean? }` (pozycja, imię, klucz klasy `"@class.<Id>.name"`, tag, poziom, procent poziomu, wynik, data dla list, znacznik własnego wiersza), `export type Snapshot = { id: string, kind: Kind, format: Format, rows: { Row }, me: { r: number?, l: number?, p: number?, hidden: boolean?, below: number? }?, at: number, mode: "global" | "local", loading: boolean? }`.
- `Leaderboard.rows(def, entries: { { key, score } }, metaOf: (key) -> Meta?, isExcluded: (userId) -> boolean, myKey: string?): { Row }`: filtruje wykluczonych (wpisy zapisane, zanim ktoś trafił do `AdminUserIds`), numeruje od 1 po filtrze, uzupełnia z metadanych, brak metadanych → `n = ""` (okno pokaże `leaderboard.unknown`), poziom i procent z `decodeLevel` dla `format = "level"`.
- `Leaderboard.mergeLocal(entries, key, score: number?, max): entries`: wstawia / przesuwa / usuwa (`score == nil`) własny wynik w kopii listy, przycina do `max` (serwer po własnym zapisie od razu widzi swój wynik, bez czekania 5 min; test).
- `Leaderboard.rankOf(rows, myKey)`; `Leaderboard.me(character, rows, cfg, excluded): me` (pozycja z listy albo `{ l, p }` „poza top”, `{ below = minLevel }` poniżej `minLevel`, `{ hidden = true }` dla wykluczonego).
- `Leaderboard.slice(rows, from, n)` (strony dla planszy i ewentualnych stron okna).

**B7. Listy (Sala Sław, przyszłe posągi).**
- `export type ListEntry = { k: string, n: string, c: string?, u: number?, at: number }`.
- `Leaderboard.listInsert(list: { ListEntry }?, entry: ListEntry, max: number, mode: "first" | "latest"): ({ ListEntry }?, string?)`: kopia; ten sam `k` już jest → `nil, "dup"` (bez zapisu: idempotentnie); `mode = "first"` i lista pełna → `nil, "full"`; inaczej dopisuje i sortuje rosnąco po `at` (przy remisie po `k`); `mode = "latest"` dopisuje i odcina najstarsze ponad `max`. Wynik nadaje się wprost jako `mutate` dla `KeyStore.update` (C3).
- `Leaderboard.placeOf(list, key): number?`.

**B8. Panele planszy.** `Leaderboard.townPanels(panels: { PanelDef }, read: (boardId) -> Snapshot?): { { id, titleKey, kind, columns: { { titleKey: string?, rows: { Row } } } } }`: panel `top` = jedna kolumna z `slice(rows, 1, n)`; panel `lists` = kolumna na tablicę (tytuł = `nameKey` tablicy). **B9. Daty.** `Leaderboard.dateParts(unix: number): { d: string, m: string, y: string }` przez `os.date("!*t", unix)` z zerami (`"07"`); klient składa z `leaderboard.date`.
