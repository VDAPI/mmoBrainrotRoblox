### A. Dane i konfiguracja

**A1. `src/shared/Data/ScheduledEvents.luau` (nowy, ok. 90 linii).** Moduł zamrożony (`table.freeze`), bez API Roblox, bez `require` innych danych (regiony jako id map, jak `Data/WorldEvents.regions` z S101). Kształt (wspólny z S130, która dopisze wpis `tourney` do `list`; nazwy pól są kontraktem dla S130):

```lua
--!strict
-- Wall-clock events (DESIGN-17 §7-§8): every server computes the same occurrences from the UTC clock
-- (Util/Clock.now, Logic/Schedule), with no cross-server messages. S129: the Blood Moon; S130 adds the
-- Champion's Tournament to `list`.

export type Slot = { weekday: number, hour: number, minute: number } -- ISO weekday: 1 = Monday ... 7 = Sunday, UTC
export type EventDef = {
	key: string, -- "bloodmoon"; also the prefix of ids and Locale keys
	nameKey: string, -- "bloodmoon.name"
	descKey: string,
	slots: { Slot }, -- at most one slot per UTC day (the occurrence id is the date, Logic/Schedule.idOf)
	duration: number, -- seconds
	warn: { number }, -- announcements, seconds before the start (descending)
	blocksWorldEvents: boolean, -- S101 world events must not overlap it (Logic/Schedule.blocking)
	quietBefore: number, -- seconds before the start in which no world event may run (with blocksWorldEvents)
	enabled: boolean,
}

local BLOODMOON: EventDef = table.freeze({
```

**B1. `src/shared/Logic/Schedule.luau` (nowy, ok. 160 linii; czysty, wymaga tylko `Logic/Time` i typów `Data/ScheduledEvents`).** Wszystkie funkcje biorą `now` / czas jako argument (serwer i klient podają `Clock.now()`):

- `export type Occurrence = { key: string, id: string, startsAt: number, endsAt: number }`.
- `Schedule.weekday(t: number): number` = ISO dzień tygodnia UTC (1 = poniedziałek … 7 = niedziela), `((Time.dayNumber(t) + 3) % 7) + 1` (1970-01-01 = czwartek = 4; test).
- `Schedule.ymd(day: number): (number, number, number)` = rok, miesiąc, dzień z numeru dnia UTC (algorytm „civil from days”, czysta arytmetyka całkowita, **bez `os.date`**, żeby działało tak samo w Lune i w Roblox). `Schedule.dateKey(t) = string.format("%04d%02d%02d", ymd(dayNumber(t)))`.
- `Schedule.startOf(slot: Slot, week: number): number` = `Time.weekStart(week) + (slot.weekday - 1) × 86400 + slot.hour × 3600 + slot.minute × 60`.
- `Schedule.idOf(def, startsAt): string` = `dateKey(startsAt)` (np. `"20261013"`; dane gwarantują najwyżej jeden slot dziennie, test). To jest `id` z kontraktu (`character.bloodMoon.id`, `BloodMoon_<id>_<region>`); S130 użyje tego samego dla `Tourney_<data>_<przedział>`.
- `Schedule.current(def, now): Occurrence?`: wystąpienie z `startsAt <= now < endsAt` (sprawdź tydzień `weekNumber(now)` i poprzedni, bo wydarzenie z niedzieli późnym wieczorem może trwać po północy poniedziałku); `def.enabled == false` → `nil`.
- `Schedule.next(def, now): Occurrence?`: najwcześniejsze wystąpienie z `startsAt > now` (ten i następny tydzień); `enabled == false` → `nil`.
- `Schedule.crossed(def, occ, from, to): { number }`: które ogłoszenia z `def.warn` (sekundy przed startem) wypadają w przedziale `(from, to]`, w kolejności malejącej; plus `0` (start), gdy `from < occ.startsAt <= to`. Pętla serwera woła to z poprzednim i bieżącym czasem kroku, więc każde ogłoszenie pada **dokładnie raz**, także po przycięciu pętli (zamrożenie serwera, `/time`), a serwer wstający w środku okna nie ogłasza zaległych ostrzeżeń (pierwszy krok ma `from = now`).
- `Schedule.blocking(list: { EventDef }, from: number, to: number): Occurrence?`: pierwsze wystąpienie wydarzenia z `blocksWorldEvents`, którego okno `[startsAt - quietBefore, endsAt)` przecina `[from, to)`; `nil`, gdy nic. Używa go `WorldEventService` (C4) i S130.
- `Schedule.untilNext(def, now): number?` = sekundy do `next(def, now).startsAt` (HUD, okno).
