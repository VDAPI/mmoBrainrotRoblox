### B. `src/shared/Logic/PathView.luau` (nowy, czysty, ok. 180 linii)

Nagłówek: `-- What the skills window and the "!" badge show about paths (S59, ROZWOJ 4): tab state, rows with the reason they are closed, node states, the weapon text, pending breakpoints and rank-ups on level-up. Pure; the window computes nothing itself.` Moduł buduje funkcje w `PathView.with(api: Paths.Api)` (czyta `api.source`), a eksportuje `PathView.with(Paths)` uzupełnione o `with` i typy (wzór `withSource` z S57; żadnego globalnego przełącznika).

```lua
export type TabState = "main" | "dip" | "closed"
export type NodeView = {
	node: PathData.PathNode,
	rank: number,
	scale: number, -- Paths.nodeScale: < 1 for team nodes in rows 1..DIP_ROWS outside the main path
	active: boolean, -- listed by Paths.activeNodes (works right now)
	weaponOk: boolean, -- node.weapon fits (true when the node has none)
	canBuy: boolean,
	buyReason: string?,
	canRefund: boolean,
	refundReason: string?,
	taken: boolean, -- choice row: the other node has ranks and this one has none
}
export type RowView = {
	index: number,
	level: number,
	need: number,
	have: number, -- ranks bought in this path's lower rows
	kind: PathData.RowKind,
	choice: boolean,
	open: boolean,
	closedKey: string?, -- paths.closed.level | paths.closed.main | paths.closed.need
	closedArgs: { [string]: number }?,
	weaponBlocked: boolean, -- main path, index > DIP_ROWS and the path weapon does not fit
	nodes: { NodeView },
}
export type View = {
	path: PathData.PathDef,
	state: TabState,
	weaponOk: boolean,
	spent: number,
	main: { ok: boolean, reason: string?, cost: ("free" | "scroll")? }, -- Paths.canChooseMain
	rows: { RowView },
}
export type Pending = { skillId: string, at: number }
export type Attention = { points: boolean, base: boolean, paths: { [string]: boolean }, any: boolean }
```

| Funkcja | Działanie |
|---|---|
| `tabState(character, pathId): TabState` | `"main"`, gdy `character.path.main == pathId`; `"closed"`, gdy `character.level < PathData.ROWS[1].level` (rząd 1 jeszcze zamknięty, poniżej 10. poziomu); inaczej `"dip"` (początki) |
| `path(character, pathId, weapons): View?` | `nil` dla ścieżki spoza klasy. Rzędy z `api.rowsFor(class)` i `def.rows[i]`; `have` = suma rang węzłów tej ścieżki w rzędach `< i`; `open, key = api.rowOpen(character, pathId, i)`, a `key` przemapowany: `paths.error.level` → `paths.closed.level` z `{ level = row.level }`, `.main` → `paths.closed.main`, `.need` → `paths.closed.need` z `{ need = row.need, have = have }` (inny klucz przechodzi bez zmian); `weaponBlocked` jak w typie; węzły: `rank = path.nodes[id] or 0`, `scale = api.nodeScale(...)`, `active` ze zbioru id z `api.activeNodes(character, weapons)` liczonego raz, `api.canBuy` / `api.canRefund` z powodami, `taken` tylko w rzędzie wyboru; `main` z `api.canChooseMain`; `spent` = suma rang tej ścieżki |
| `weaponText(req: WeaponReq?, lang: string?): string` | tekst wymogu broni przez `Locale.T`: dwuręczne typy z `main` osobno (`api.isTwoHanded`), jednoręczne z `main` zgrupowane jako `"A / B + C / D"` z drugą ręką (bez drugiej ręki po prostu `"A / B"`), przy `main = nil` i `offhand` `"{paths.weapon.anyOneHand} + C"`; części łączone słowem `paths.weapon.or` ze spacjami; `nil` albo oba pola puste → `paths.weapon.any`. Nazwy typów z `itemBase.<typ>`. Przykład PL: Niszczyciel „Kostur albo Różdżka + Kula”, Kapłan Fortuny „dowolna broń jednoręczna + Relikwia” |
| `pendingBreakpoints(character): { Pending }` | dla każdej aktywnej z `api.availableSkills(character)`: dla `at` z `Skills.BREAKPOINT_LEVELS`, gdy `skill.breakpoints[at].b` istnieje, `api.skillRank ≥ at` i brak wpisu `path.bp[Skills.choiceKey(id, at)]` |
| `attention(character): Attention` | `points`: `api.free(character) ≥ 1` i co najmniej jeden węzeł ścieżek klasy przechodzi `api.canBuy` (wtedy też `paths[pathId] = true` dla każdej takiej ścieżki); z `pendingBreakpoints`: umiejętność bez `path` → `base = true`, z `path` → `paths[skill.path] = true`; `any` = cokolwiek z powyższych |
| `rankUps(character, fromLevel, toLevel): { { skillId: string, rank: number } }` | pusta, gdy `toLevel <= fromLevel`; dla umiejętności z `api.source.classSkills(class)` w kolejności danych: `r0` i `r1` = `api.skillRank` na płytkiej kopii postaci z `level = fromLevel` / `toLevel`; wpis, gdy `r0 > 0` i `r1 > r0` (nowo odblokowane ma swój toast z S56) |
| `newBreakpoints(character, fromLevel, toLevel): { Pending }` | aktywne z `r1 > 0`: dla `at` z `r0 < at <= r1`, z opcją B i bez wpisu w `path.bp` |

`attention` i `rankUps` dostają postać zbudowaną z wąskich gałęzi stanu (`{ class, level, path }`, przy `path` też `hotbar` i `equipment`, jeśli funkcje S57 ich potrzebują); żadna funkcja nie zakłada, że są inne pola.
