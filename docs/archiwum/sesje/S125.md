## Kontekst

Właściciel chce „rankingi graczy wg poziomu” i zaakceptował propozycję rankingów globalnych („rankingi globalne — git”, cytat na końcu). `docs/DESIGN-17.md` §5 dzieli je na dwie sesje: S124 (poziom, Sala Sław, okno, plansza) i **S125** (ta): tygodniowy EXP z nagrodami, ranking gildii, opcjonalny eksport na wiki. Kontrakt S125 w całości:

- `exp_week` (MemoryStore SortedMap na klucz tygodnia, TTL 8 dni): wynik = EXP zdobyty w tym tygodniu (z potworów, questów i wydarzeń; przyrost wysyłany partiami co 60 s). Koniec tygodnia: top 3 na każdym przedziale poziomów (`brackets = { {1,19}, {20,44}, {45,69}, {70,100} }`, przedział wg poziomu postaci w chwili ostatniego zapisu; osobna SortedMap na przedział) dostaje tytuł „Najpilniejszy tygodnia” na 7 dni (`character.timedTitles`) i odłamki 100/50/25 pocztą. Wypłatę robi pierwszy serwer, który zdobędzie blokadę (`UpdateAsync` na kluczu `"paid_<tydzień>"`), idempotentnie.
- `guild` (tablica gildii: suma poziomów 10 najwyższych członków, aktualizowana przez `GuildService` przy zmianie składu/awansie, z limitem zapisów).
- Eksport na wiki (opcjonalny): `tools/rankings_fetch` (Lune lub Node) czyta top 100 przez Roblox Open Cloud (OrderedDataStore API) i zapisuje `wiki/src/data/rankings.json`; workflow GitHub co godzinę tylko gdy istnieje sekret `ROBLOX_OPEN_CLOUD_KEY` (inaczej krok pomija się na zielono). Strona wiki „Rankingi” pokazuje dane albo informację „ranking dostępny w grze”. Ostatnia wiadomość sesji mówi właścicielowi, jak dodać klucz.

Błąd `"done"` → `paidWeeks[W] = true`, wczytaj zwycięzców (D3), koniec. `"busy"` → spróbuj przy następnym sprawdzeniu.

Zwycięzcy: jeśli rekord ma już `winners` (przejęta wypłata), użyj ich; inaczej dla każdego przedziału `Stores.sorted(weekMapName(W, b), weekTtl):top(#WEEK_REWARDS.shards + 2)` (zapas na wpisy z `s = 0` albo złym kluczem), `Leaderboard.payoutPlan(W, tops)`, zapis listy zwycięzców (imię, klasa, poziom, przedział, miejsce, EXP; **bez** `userId` w części, którą widzi klient) do rekordu przez `update`, zanim cokolwiek wyślesz.
3. Dla każdego `Payout` bez `record.sent[key]`: **najpierw oznacz** (`update`: `sent[key] = true`), **potem wyślij** `MailService.Send(userId, { from = "system", subjectKey = "mail.subject.weeklyRank", args = { place = place, bracket = Leaderboard.bracketLabel(b), week = <data poniedziałku tygodnia W jako "YYYY-MM-DD"> }, shards = shards, timedTitle = { id = title, untilTs = untilTs }, charId = charId })`; przy błędzie wysyłki cofnij oznaczenie (`sent[key] = nil`) i przerwij (następna próba dokończy). Wzór „oznacz–wyślij–cofnij” jak `CodeService.redeem` / S100 (Kontekst). Awaria serwera między oznaczeniem a wysyłką = jedna utracona nagroda, nigdy podwójna (linia w DECYZJE).
4. Na końcu `update`: `state = "done"`, `doneAt = now`; `paidWeeks[W] = true`; log `info` z liczbą przesyłek; `Analytics.custom` (np. `"WeeklyRankPaid"`, liczba przesyłek) przez gracza nie da się (brak gracza): wystarczy log.
5. Cała wypłata w `task.spawn` (yielduje), nigdy w kroku gry; jeden przebieg naraz na serwer (`paying = true`).
6. Wysyłka do postaci, która w międzyczasie została usunięta: przesyłka z `charId` usuniętej postaci nie będzie widoczna (`Mail.visible`); przyjmujesz to (usunięcie postaci = rezygnacja), linia w DECYZJE.

**D3. Zwycięzcy poprzedniego tygodnia dla UI.** Po `done` serwer czyta rekord `paid_<W>` (raz, potem w pamięci do zmiany tygodnia) i trzyma `lastWinners = { week = W, [b] = { { place, name, class, level, exp } } }`; okno pokazuje je w zakładce „Tydzień” (G1). Bez rekordu (pierwszy tydzień, atrapa po restarcie) sekcji nie ma (bez pustego nagłówka).

**D4. Powiadomienie.** Odbiorca online dostaje toast `mail.arrived` sam (`Notify`, Kontekst). Dodatkowo, gdy serwer zakończy wypłatę, każdy serwer przy najbliższym odczycie rekordu (D3) może pokazać graczom online, którzy są na liście zwycięzców (po `charId` aktywnej postaci), toast `leaderboard.week.won` `{ place, bracket }` raz (pamięć serwera). Bez ogłoszeń globalnych (DESIGN-17 tego nie wymaga).

### H. Admin

Wpisy w `Data/AdminCommands.luau`, `commands.<nazwa>` w `Admin/<Kategoria>.luau`, `admin.usage.<nazwa>` PL i EN, odpowiedzi przez `Context.reply`. `"LeaderboardService"` w `AdminService.Deps` (S124 dopisała; sprawdź), `"TitleService"`, jeśli go brakuje. S124 ma ogólną komendę `/lb` (`info`, `refresh`, `submit`, `hide`, `show`, `remove`, `fake`, `hofclear`; teksty `admin.lb.*`): tydzień i gildie dostają osobne komendy poniżej (inne argumenty i działania), a `/lb fake <n>` (tylko atrapa) **rozszerz** tak, żeby wypełniał też bieżący `exp_week_<tydzień>_<1..4>` i `guild` (gracze testowi z tymi samymi imionami, wynik malejący deterministycznie), bo inaczej zakładki „Tydzień” i „Gildie” są w Studio puste. `/lb hide` usuwa też wpis tygodnia gracza (przedział `expWeek.b`).
- `cmd("world", "rankweek", { enum("action", { "info", "flush", "pay", "reset", "add" }), int("value", 0, 100000000, true) }, { dangerActions = { "pay", "reset" } })`:
  - `info`: tydzień, czas do końca, `expWeek` postaci, przedział, czy atrapa, stan wypłaty poprzedniego tygodnia (`admin.rank.week` `{ week, left, exp, bracket, mock, paid }`);
  - `flush`: natychmiastowy `writeWeekly` gracza (bez limitu) i odświeżenie cache tygodnia (`admin.rank.flushed`);
  - `pay`: wypłata tygodnia `value` (domyślnie poprzedniego) tą samą ścieżką co D2, łącznie z blokadą (idempotentna: drugi raz odpowiada `admin.rank.paid` „już wypłacony”); bieżący tydzień też można wypłacić (test na serwerze testowym), linia w odpowiedzi;
  - `reset`: tylko atrapa albo Studio (na żywym serwerze `admin.rank.liveOnly`): czyści mapy bieżącego tygodnia i rekord wypłaty w atrapie;
  - `add`: dolicza `value` EXP do **tygodnia** postaci (tylko `expWeek`, bez prawdziwego EXP; do testów rankingu; źródło `"admin"` dla prawdziwego EXP dalej nie liczy się do tygodnia) i oznacza `dirty`.
- `cmd("guild", "rankguild", { enum("action", { "info", "push" }) })`: `info` = wynik gildii postaci (suma, dekodowany, pozycja z cache), `push` = `SubmitGuild` od razu z pominięciem limitu (`admin.rank.guild` `{ score, rank }`).
- Nadanie tytułu czasowego do testów: `cmd("character", "timedtitle", { str("id"), int("days", 0, 365, true, "7") })` → `TitleService.GrantTimed(player, id, now + days × 86400)`; `days = 0` zdejmuje (zapis `timedTitles[id] = nil`) (`admin.title.timed` `{ id, until }`, nieznany / nie-czasowy → `admin.title.notTimed`).
- `/time +s` (S10, `Clock`) przesuwa zegar także dla tygodnia: wpisz to w `admin.usage.rankweek` („przesuń czas `/time`, żeby sprawdzić koniec tygodnia”).
