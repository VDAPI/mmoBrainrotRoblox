### B. `src/shared/Logic/EffectStack.luau` (nowy, czysty, ok. 120–150 linii)

Wymaga tylko `../Data/BuffCategories` (ścieżka tekstowa, działa w Lune i w grze). Komentarze po angielsku.

1. **Wpis:**
   ```lua
   export type Entry = {
   	category: string?, -- nil or unknown id = own
   	value: number?, -- kinds without stats: damageReduction, slow, vulnerability, armorBreak, misfortune
   	stats: { [string]: number }?, -- statBuff
   	pct: boolean?, -- statBuff: percentage modifiers instead of flat
   	at: number, -- when it was (re)applied; a tie goes to the newer one
   }
   ```
2. `isOwn(category: string?): boolean` = `nil`, `"own"` albo id spoza `BuffCategories.byId` (w grze nieznane id nie może wywrócić walki; test danych pilnuje, że go nie ma).
3. `strength(entry): number`: kategoria ze `stats` → suma `entry.stats[stat]` po **zadeklarowanych** statystykach kategorii (statystyka spoza listy nie liczy się do siły); kategoria bez `stats` → `entry.value or 0`.
4. `select(entries): { Entry }`: wszystkie wpisy własne (`isOwn`) plus z każdej kategorii jeden najsilniejszy; remis siły → większe `at`; pełny remis → pierwszy z listy (deterministycznie). Grupuj po id kategorii w funkcji pomocniczej, żeby S63 mogła dołożyć podział „umiejętność / przedmiot” w jednym miejscu.
5. `stats(entries): (flat: { [string]: number }, pct: { [string]: number })`: suma wybranych wpisów (`pct == true` → `pct`, inaczej `flat`). Wkład kategorii z limitem w `caps[category.id]` (dziś `allyMove`) przycinasz do limitu na każdą statystykę. Wpisy własne bez przycinania (to balans klasy).
6. `combine(values: { number }, cap: number): number` = `min(cap, 100 × (1 − Π(1 − clamp(r, 0, 100)/100)))` w procentach. `reduction(entries): number` = `combine` z wartości `select(entries)` i `BuffCategories.caps.damageReduction`. Przykład z kontraktu: 60 (`own`) i 15 (`allyGuard`) → 66.
7. `merge(old: Timed?, new: Timed, now: number): ({ [string]: number }?, number)`, gdzie `Timed = { stats: { [string]: number }?, pct: boolean?, expiresAt: number }`: ponowne nałożenie `statBuff` z tym samym kluczem (ROZWOJ 7.2). Gdy `old` istnieje, `old.expiresAt > now` i `old.pct == new.pct`: statystyki to suma zbiorów kluczy, przy powtórzonej statystyce wartość nowsza; koniec = `max(old.expiresAt, new.expiresAt)`. Inaczej (brak, wygasły albo inne `pct`) → statystyki i koniec nowego. Zwraca kopię, nigdy nie mutuje wejścia.
8. **Atrybut `Effects`** (wspólny kodek serwera i klienta):
   - `VALUE_KINDS = { slow, vulnerability, armorBreak, damageReduction, manaShield, nextShot }` (rodzaje, w których `value` to procent pokazywany graczowi; tarcza `shield` ma w `value` resztę punktów, więc jej nie pokazujemy);
   - `encode(list: { { kind: string, expiresAt: number, value: number? } }, now: number): string?`: pomija wpisy z `expiresAt <= now`, **jeden wpis na rodzaj**: najpóźniejszy koniec i najwyższa wartość (tylko `VALUE_KINDS`, tylko `> 0`), format `kind:<floor(expiresAt × 10)/10>` albo `kind:<…>:<round(value)>`, rodzaje posortowane alfabetycznie (stały napis, gdy nic się nie zmienia), `nil` dla pustej listy;
   - `decode(raw: any, now: number): { { kind: string, left: number, value: number? } }`: dzieli po `;`, wzorzec `^(%a+):([%d%.]+):?(%d*)$` (stary format bez wartości też przechodzi), pomija `left <= 0` i śmieci, grupuje po rodzaju (najdłuższy `left`, najwyższa `value`), sortuje po `kind`; dla wartości innej niż napis zwraca `{}`.
