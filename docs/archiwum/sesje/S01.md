# S01: Fundament projektu, dane gracza, wybór postaci

> Skopiuj CAŁY ten plik jako pierwszą wiadomość w nowej sesji Claude Code (w folderze repozytorium).

Jesteś Claude Code i budujesz grę **Vaelthorn**: MMORPG na Roblox (Luau, Rojo, Wally, Fusion, ProfileStore), działające jak Margonem, tylko w 3D. Repozytorium: https://github.com/VDAPI/mmoBrainrotRoblox (gałąź `main`). To **długa sesja implementacyjna (2–3 h pracy)**. Zakres jest celowo duży.

## Zasady sesji (obowiązkowe)

1. **Na start przeczytaj** `CLAUDE.md`, `docs/DESIGN.md`, `docs/ARCHITECTURE.md`, `docs/PROGRESS.md` (szczególnie „Decyzje”, „Niedokończone” i „Zgłoszone błędy”). Kod czytaj tylko w zakresie potrzebnym do tej sesji.
2. **Nie testuj w Roblox Studio i nie uruchamiaj gry.** Właściciel projektu testuje sam po sesji. Nie pytaj go o nic w trakcie.
3. Wolno i należy: pisać **testy jednostkowe** czystej logiki (`src/shared/Logic`) i spójności danych (`src/shared/Data`) w `tests/`, uruchamiać `scripts/check` (StyLua, Selene, luau-lsp, Lune) i naprawiać zgłoszone błędy. Nie poświęcaj na to więcej niż ok. 10% czasu sesji.
4. **Pracuj autonomicznie do końca zakresu.** Przy niejasności wybierz rozwiązanie najbliższe `DESIGN.md` i zapisz decyzję w `docs/PROGRESS.md` → „Decyzje”.
5. Kolejność pracy: dane i logika → serwisy serwera → sieć → kontrolery i UI klienta → efekty i dopieszczenie. Gdy brakuje czasu, **kończ rzeczy rozpoczęte** zamiast zaczynać nowe; resztę wpisz w „Niedokończone”. Żadnych pustych zaślepek udających gotową funkcję.
6. Liczby balansu tylko w `src/shared/Data/*` i `Config.luau`. Teksty dla gracza tylko przez `Locale` (klucze w `pl.luau` i `en.luau`, oba języki). Kod i komentarze po angielsku.
7. Serwer jest autorytetem: waliduj typy, dystans i rate-limit w każdym handlerze remote'a.
8. UI: poważne fantasy wg `DESIGN.md` §23 i `UI/Theme.luau`, wszystko działa też dotykiem (mobile).
9. Dodaj **komendy admina** potrzebne do szybkiego sprawdzenia tej sesji (zob. `ARCHITECTURE.md` §11).
10. **Na koniec sesji:**
    - zaktualizuj `docs/PROGRESS.md`: sekcja tej sesji (co zrobiono, lista plików), „Decyzje”, „Niedokończone” oraz **„Instrukcja testu S01”**: ponumerowane kroki dla właściciela w Studio (jakie komendy wpisać, co kliknąć, czego się spodziewać), max ~25 kroków;
    - uruchom `scripts/check` i napraw błędy;
    - `git add -A`, `git commit -m "S01: <krótki opis>"`, `git push origin main`.
    - Ostatnia wiadomość do właściciela: 5–10 linii podsumowania + odesłanie do „Instrukcja testu S01”.

## Kontekst
Repozytorium jest **puste** poza folderem `docs/` (właściciel wrzucił tam `DESIGN.md`, `ARCHITECTURE.md`, `PROGRESS.md`). Właściciel pracuje na **Windows**, ma VS Code i Roblox Studio z pluginem Rojo. Twoim zadaniem jest zbudowanie całego fundamentu, na którym stanie reszta gry, oraz pierwszego grywalnego ekranu: wyboru i tworzenia postaci.

## Zakres

### 1. Narzędzia i konfiguracja repo
- `rokit.toml` z: rojo, wally, wally-package-types, stylua, selene, luau-lsp, lune (aktualne stabilne wersje). Jeśli Rokit nie jest zainstalowany, w README opisz instalację (`winget`/instalator), ale konfiguracja ma być kompletna.
- `wally.toml` (realm shared: Fusion 0.3, Signal, Promise, Trove; server: ewentualnie nic). `wally install`, a typy przez `wally-package-types`. Paczki w `Packages/` i `ServerPackages/` dodaj do `.gitignore` **lub** commituj (wybierz commitowanie, żeby właściciel nie musiał nic instalować do `rojo serve`; zapisz decyzję).
- ProfileStore: zainstaluj z Wally, jeśli jest; w przeciwnym razie pobierz oficjalny moduł do `src/server/Vendor/ProfileStore.luau`.
- `default.project.json` mapujący strukturę z `ARCHITECTURE.md` §2 (Shared, Server, Client, Packages, Remotes tworzone w runtime, `Assets` foldery). Ustaw `Players.CharacterAutoLoads = false` przez właściwości w projekcie, `Workspace.StreamingEnabled = true`.
- `selene.toml` (std roblox), `stylua.toml` (tabs lub 4 spacje, kolumna 120), `.luaurc` (strict, aliasy jeśli potrzebne), `.gitignore` (sourcemap.json, *.rbxl*.lock itp.).
- `scripts/check.ps1` i `scripts/check.sh` (zob. ARCHITECTURE §1), pobieranie `globalTypes.d.luau` dla luau-lsp.
- `README.md` dla właściciela: instalacja narzędzi na Windows krok po kroku, `rojo serve`, połączenie w Studio, włączenie dostępu do API (Game Settings → Security → Enable Studio Access to API Services), uruchamianie `scripts/check.ps1`.
- `CLAUDE.md`: zwięzłe (≤ 80 linii) zasady dla przyszłych sesji: gdzie co leży, konwencje, „nie testuj w Studio”, „aktualizuj PROGRESS”, jak uruchomić check, jak dodać serwis/kontroler/remote/ekran/klucz lokalizacji.

### 2. Szkielet kodu
- `src/server/init.server.luau` i `src/client/init.client.luau`: loader z `Init`/`Start` i zależnościami (ARCHITECTURE §3), wyraźne logi czasu startu każdego serwisu.
- `Shared/Net` (ARCHITECTURE §4): definicje, tworzenie remote'ów, rate-limit token bucket, `Net.Check` do walidacji argumentów, obsługa event/function.
- `Shared/Util`: `Log`, `TableUtil` (deepCopy, deepEqual, merge), `Format` (liczby z separatorami, czas mm:ss / hh:mm:ss, krótkie 1.2k/3.4M), `Locale` (T(key, args) z `{name}`-podstawieniem, fallback en → klucz).
- `Shared/Types.luau`: typy z ARCHITECTURE §5 (AccountData, CharacterData, ItemInstance, Slot, ClassId itd.).
- `Shared/Config.luau`: MaxLevel, MaxCharacters = 3, AdminUserIds (pusta lista + komentarz, jak dodać ID właściciela), przełączniki debug.
- `Shared/Logic/Rng.luau`: deterministyczny RNG (np. PCG lub xorshift) z interfejsem `next()`, `int(a,b)`, `float(a,b)`, `weighted(tbl)`, `pick(arr)`, możliwość wstrzyknięcia w testach.
- `Shared/Data/Classes.luau`: 4 klasy z DESIGN §4.2–4.3 (id, klucze nazw, główna stat, zasób, startowe staty, dozwolone typy broni, startowy ekwipunek: lista id przedmiotów do nadania później).
- `tests/run.luau` (mini runner) + pierwsze testy: Rng (zakresy, powtarzalność z seedem), TableUtil, Locale (brakujące klucze).
- Test spójności lokalizacji: każdy klucz z `pl.luau` istnieje w `en.luau` i odwrotnie.

### 3. Dane gracza
- `DataService`: ProfileStore, szablon `AccountData`, `Reconcile`, migracje (`schema`), mock w Studio gdy brak API (z wyraźnym komunikatem w output), kick z komunikatem przy błędzie sesji, zapis przy wyjściu, `BindToClose`.
- `PlayerStateService` (ARCHITECTURE §6): Set/Update/ArrayInsert/ArrayRemove z batchowanymi diffami; pełny snapshot przy wejściu; wybór aktywnej postaci.
- Klient `UI/State.luau`: kopia danych + `State.Value(path)` jako Fusion Value z cache, aktualizacja z diffów.
- `NameService`: rezerwacja unikalnych nazw postaci w DataStore `Names` (UpdateAsync, właściciel = userId:slot), zwolnienie przy usunięciu postaci, filtr TextService (`FilterStringAsync` + `GetNonChatStringForBroadcastAsync`), walidacja 3–16 znaków `[A-Za-z0-9ĄąĆćĘęŁłŃńÓóŚśŹźŻż]`. Mock w Studio.

### 4. Postacie
- `CharacterService`: listowanie slotów, tworzenie (klasa, nazwa), usuwanie (wymaga wpisania nazwy), wybór i wejście do gry, „zmień postać” (zapis, usunięcie modelu, powrót do ekranu wyboru).
- Tworzenie postaci: poziom 1, staty startowe klasy, 0 punktów, złoto 50, Płócienny Plecak (zapisz jako zwykłe pole, pełny system przedmiotów będzie w S04; użyj już teraz struktury `equipment.backpack = ItemInstance`, z id `backpack_20`), lokalizacja: miasto.
- Spawn: `LoadCharacter` dopiero po wyborze postaci; pozycja z `location` (na razie płaska platforma-miasto: prosty baseplate 512×512 z kilkoma placeholderowymi budynkami i napisem, prawdziwy świat powstanie w S08).
- Nazwa i poziom nad głową (BillboardGui: nazwa, „Lv 1 Wojownik”, później gildia).

### 5. UI bazowe (Fusion)
- `UI/Theme.luau` wg DESIGN §23 (kolory, czcionki, rozmiary, animacje, rzadkości).
- Komponenty: `Button` (warianty primary/secondary/danger/ghost, stany hover/press/disabled, dźwięk kliknięcia), `Panel`, `Window` (tytuł, przycisk zamknięcia, przeciąganie na PC, pełny ekran na mobile), `Modal` (potwierdzenie, z polem tekstowym opcjonalnie), `Toast` (kolejka powiadomień), `TextInput`, `Bar` (paski zasobów z animacją), `Tabs`, `Tooltip` (podąża za kursorem / przytrzymanie na mobile), `IconButton`.
- `WindowManager` (kontroler): rejestr okien, otwieranie/zamykanie, Esc, jedno okno modalne naraz, skróty klawiszowe.
- `UIScale` adaptacyjny, wykrywanie dotyku.
- **Ekran wyboru postaci** (`Screens/CharacterSelect`): tło (rozmyty widok kamery z miastem lub gradient), 3 karty slotów (pusta: „Utwórz postać”; zajęta: nazwa, klasa, poziom, mapa, przycisk „Graj”, „Usuń”), kreator: wybór klasy (4 duże karty z opisem roli i ikoną), pole nazwy z walidacją na żywo i błędami z serwera, przycisk „Utwórz”. Przełącznik języka PL/EN w rogu.
- **Szkielet HUD** (`Screens/Hud`): na razie nazwa, poziom, puste paski HP/Mana/Energia/EXP, przyciski menu (nieaktywne okna mogą pokazywać „wkrótce”), przycisk „Zmień postać” w menu Esc.

### 6. Admin
- `AdminService` z parserem komend z TextChatService (`TextChatCommand` lub nasłuch wiadomości zaczynających się od `/`), uprawnienia (AdminUserIds + RunService:IsStudio()), na start: `/wipe`, `/gold n`, `/shards n`, `/help` (lista komend w czacie systemowym).
