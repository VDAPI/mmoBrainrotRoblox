**B2. Wspólne zasady węzłów** (2.2, 2.3, 3.2):
- Id `<pathId>_<nazwa>`, unikalne w grze. Węzeł `skill` ma id `<pathId>_<skillId>`, `maxRank = 1`, `skill = "<skillId>"` i teksty swojej umiejętności (`skill.<skillId>.name` / `.desc`), bez kluczy `path.*`. Pozostałe: `nameKey = "path.<pathId>.<nazwa>.name"`, `descKey = ".desc"`.
- Wartości `{ ranga 1, ranga max }`, liniowo (`{ 4, 10 }` daje 4 / 7 / 10). **Środkowe rangi w tabelach ROZWOJ 9.3–9.5 są zaokrąglone** (Łaska Fortuny „+2 / +5 / +7” to 2 / 4,5 / 7, Żarliwość „0,3 / 0,6 / 1” to 0,3 / 0,65 / 1): dane są liniowe, bez wyjątków. Liczby zależne od rangi wpisujesz w `node.values` według konwencji B3 z S57 (Kontekst; wzór: ścieżka testowa w `tests/fixtures/paths.luau`): `passive` i `luck` wskazują nazwę pola, a w `modify.bp` liczba to `{ ref = "<pole>" }`. „← `pole = { a, b }`” w tabelach znaczy: `node.values.pole = { a, b }`, a w `modify` w tym miejscu stoi `{ ref = "pole" }` (np. `healer_salvation`: `values = { salvation = { 0.92, 0.75 } }`, `modify = { skill = "divineIntervention", bp = { mul = { cooldown = { ref = "salvation" } } } }`; `inquisitor_executioner`: `bp = { execute = { ref = "executioner" } }`). Nazwy pól `node.values` nie powtarzają nazw pól umiejętności (`shieldBody`, nie `shieldHp`).
- Konwencja S57 obejmuje `values`, `add`, `mul` i klucze zachowań, więc `Paths.skillMods` **nie rozszerzasz**. Liczby zachowań (`stunSplash`, `shieldBurst`, `misfortune`) celowo idą przez `values` umiejętności (`bp.values.<pole> = { ref = … }`, wzór `armorBp` z S55), czytane przez `ctx.value(...)`; sam klucz zachowania ma tylko stały promień.
- Rzędy 3, 6 i 9 mają `choice = true` i po dwa węzły; rząd 8 jeden węzeł `skill` (zwieńczenie), rząd 11 jeden węzeł `modify` z `maxRank = 2`.
- `dipScale` zostaw domyślne (`DIP_SCALE = 1/3`, bez pola w węzłach). W rzędach 1–2 efekt z kategorią ma tylko **Złe Oko** (`fortune_evilEye`, `enemyMiss`): `isTeamNode` uznaje je za drużynowe (efekt z kategorią inną niż `own` w `modify.bp`), więc poza ścieżką główną `skillMods` mnoży jego `{ ref = "evilEye" }` w `values.misfortune` przez 1/3 (2% zamiast 6%), a stały czas 6 s zostaje. Nic nie rozszerzasz. Tarcza, leczenie, Wskrzeszenie i pasywki rzędów 1–2 są bez kategorii, więc działają w pełni. Węzły `luck` nie podlegają `dipScale` (S60).
- `node.weapon` mają tylko węzły rzędu 3 Inkwizytora (`{ offhand = { "shield" } }` i `{ offhand = { "relic" } }`); działają tylko z tą drugą ręką, oprócz broni ścieżki.
- `glyph`: jeden znak jak w `Data/Skills`; węzeł `skill` bierze glyph swojej umiejętności.

### C. Haki i zachowania węzłów (kod)

Najpierw sprawdź grepem, co już jest (S62, S64, S69, S70 mogły część zrobić). Każdy punkt to kilkadziesiąt linii, bez nowych systemów. Stałe idą do `Data/Skills/init.luau` obok `WOUNDED_RADIUS` (nie do `Data/Combat`, eksportowanego w całości na wiki): `LOW_HP_HEAL = 35` (% życia celu) i `HEAL_CRIT_MUL = 1.5`.

**C1. `ctx.heal`: `allyHealBonus`, `lowHpHealBonus`, `healCrit`** (ROZWOJ 9.3, 9.4, 14.1; `Skills/Context.luau`, dziś 296–311).
- Dopisz czystą funkcję `Skills.healBonusPct(hooks: { healBonus: number, allyHealBonus: number, lowHpHealBonus: number }, isOther: boolean, fraction: number): number` = `healBonus + (isOther ? allyHealBonus : 0) + (fraction < LOW_HP_HEAL / 100 ? lowHpHealBonus : 0)`. Premie się **sumują** (ROZWOJ 9.4: pełny Uzdrowiciel leczy innych ×1,64 = 1 + (25 Pobożność + 9 + 15 + 15) / 100). `fraction` to życie celu przed leczeniem / maks. życie.
- W `Context` jedna funkcja pomocnicza (np. `healFactor(target, shield: boolean)`) dla `ctx.heal`, sumy `hot` przy rzuceniu, tarczy z nadmiaru (`healOne`) i `Support.shield`. Leczenie: `1 + healBonusPct / 100`, potem to, co już tam mnożą S61 i S62 (`healPower`, PvP ×0,7), potem krytyk. **Tarcze** dostają to, co po S69, plus krytyk; `allyHealBonus` i `lowHpHealBonus` dotyczą tylko leczenia (ROZWOJ 9.3). Nie ruszaj `Skills.healMul` (S54) ani `ctx.healMul` (Światłość). Od S65 `ctx.heal` tylko deleguje do `Context.healFrom(healer, target, amount)`, z którego leczy też sojusznika Zbawczy cios Kostura Świętego (S65): mnożnik leczenia wstaw w `healFrom`, żeby została jedna ścieżka (Zbawczy cios na sojuszniku dostaje wtedy te same premie i krytyk; jedna linia w DECYZJE). Część Zbawczego ciosu dla noszącego (`ResourceService.Heal`, jak wampiryzm) zostaje bez zmian. S73 przepina tarcze umiejętności na `ctx.shield` i użyje tego samego pomocnika, więc trzymaj go w `Context` pod jedną nazwą.
- **`healCrit`:** szansa = `critChance` rzucającego (pkt proc.) × `healCrit` / 10000, w [0, 1]; trafienie mnoży kwotę przez `HEAL_CRIT_MUL`. Losowanie przez `Logic/Rng` (jak `CombatService.luau:110`), nigdy `math.random`; jeden rzut na leczenie, na sumę `hot` i na tarczę. Pole krytyka w sygnale leczenia albo fx ustaw, jeśli istnieje; bez nowego UI.
- `allyHealBonus` tylko gdy cel ≠ rzucający (wampiryzm, `selfHeal` i Boski Gniew go nie dostają). Haki przez `services.PassiveHook` jak `healBonus`.

**C2. `holyHealAll` (Święty Gniew).** Leczenie Boskiego Gniewu (hak `holyStrikeHeal`, 4 → 20% zadanych obrażeń, leczy rzucającego) działa dla Światłości, Sądu, Piętna i Młota z siłą `holyHealAll / 100`. Gdyby `onHit` tych trafień nie widział, wołaj funkcję z `target`, `circleSelf` i `circleTarget`.

**C3. `zealCdr` (Żarliwość).** W `SkillService.cast`, w `finished()` (dziś 501–508), gdy `offensive` (426–430), hak `zealCdr` > 0 i nie `rt.noCooldowns`: dla `ZEAL_SKILLS = { "heal", "purify" }` z trwającym odnowieniem (`rt.cooldowns[id] > now()`) `rt.cooldowns[id] = math.max(now(), rt.cooldowns[id] - zeal)`, potem jedno `publishCooldowns(player)`.
