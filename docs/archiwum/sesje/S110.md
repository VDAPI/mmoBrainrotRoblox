Kod uruchomiony przez `execute_luau` żyje w osobnym kontekście: `require` modułu kontrolera z niego **nie** daje tej samej instancji modułu, co gra. Dlatego AnimLab wystawia `BindableFunction` (D5).

### B. Stan potwora i klipu w chwili `t` (czyste, `Logic`)

**B1. `Gait` dostaje stałe i funkcję stanu.** W `src/shared/Logic/Gait.luau`:
- `Gait.HIT_SECONDS = 0.25` i `Gait.DEATH_SECONDS = 0.55` (przeniesione z lokalnych stałych `AnimationController` :38 i :41; te same wartości, `AnimationController` i `MobVizController` czytają je z `Gait`);
- `Gait.SPAWN_SECONDS = 0.55` (MobViz używa 0,55 dla „spawn”; `AnimationController.SPAWN_SECONDS = 1.2` :39 to inna rzecz, okno wyboru klipu `spawn`, zostaje lokalne);
- nowa czysta funkcja:
```lua
export type Slot = "idle" | "walk" | "run" | "attack1" | "attack2" | "cast" | "hit" | "death" | "spawn"
export type StateOptions = {
	windup: number?, -- attack slots: seconds of the windup (default DEFAULT_WINDUP)
	speed: number?, -- walk / run: studs per second (default 8 walk, 16 run)
	scale: number?, -- walk / run: rig scale for the stride (default 1)
	seed: number?, -- offset of the idle clock (default 0)
}
-- The motion of a generated monster `t` seconds into `slot` (pure: the same arguments give the same motion).
function Gait.stateMotion(slot: Slot, t: number, options: StateOptions?): Motion
```
Reguły (te same liczby co dziś): `time = t + seed` zawsze (oddech i fale); `walk`/`run`: `move = 1`, `cycle = Gait.advance(0, t, speed, scale)`; `attack1`/`attack2`/`cast`: `raise, strike = Gait.attack(t, windup)`; `hit`: `hit = max(0, 1 - t / HIT_SECONDS)`; `death`: `dead = clamp(t / DEATH_SECONDS, 0, 1)`; `spawn`: `dead = 1 - clamp(t / SPAWN_SECONDS, 0, 1)`; `idle`: same zera poza `time`. Uwaga: `Gait.advance(0, t, …)` z jednym krokiem `dt = t` daje ten sam kąt co suma małych kroków (funkcja jest liniowa modulo 2π), sprawdź to testem.
- `MobVizController.step` przepnij na `Gait.stateMotion(state, phaseTime, { windup = 0.6, speed = 8 })` (zachowanie bez zmian; w `walk` cykl liczony od `phaseTime`, a nie narastająco: różnica niewidoczna, zapisz w DECYZJE). `AnimationController.step` zostaje na swojej logice (prędkość z fizyki), tylko czyta stałe z `Gait`.

**B2. `LookAnim` dostaje czas klipu.** W `src/shared/Logic/LookAnim.luau`:
```lua
-- TimePosition of a clip of `length` seconds `t` seconds after it started at `speed`: looped clips wrap,
-- one-shot clips stop just before the end (TimePosition = length would end the track).
function LookAnim.clipTime(t: number, length: number, looped: boolean, speed: number?): number
```
`length <= 0` → 0. Dla klipu bez pętli: `min(t * speed, length - 1/60)`, nie mniej niż 0.

**B3. Ataki i umiejętności postaci.** `AttackPose.sample` i `SkillPose.sample` są już czystymi funkcjami `t`: **nic w nich nie zmieniasz**. W SESJE zapisz jedną linię: „AttackPose / SkillPose: poza w chwili t istniała (sample), zamrożenie robi klient (D1)”.

### C. Zegar efektów: `src/client/Vfx/Clock.luau` (nowy, ok. 140 linii)

Efekty są tweenami, emiterami cząsteczek i opóźnieniami w czasie rzeczywistym, więc „zatrzymaj w chwili `t`” wymaga wspólnego zegara. Moduł (klient, API Roblox):
```lua
local Clock = {}
-- Virtual seconds: os.clock() minus the time spent frozen. Equals os.clock() offset when nothing was frozen.
function Clock.now(): number
-- task.delay on the virtual clock: never fires while frozen. One Heartbeat connection serves every call.
function Clock.after(seconds: number, fn: (...any) -> (), ...: any)
-- Creates, tracks and plays a tween; frozen tweens are paused and resumed.
function Clock.tween(instance: Instance, info: TweenInfo, goal: { [string]: any }): Tween
-- Tracks a ParticleEmitter (TimeScale 0 while frozen) or a Trail / Beam (see below); returns it.
function Clock.track<T>(item: T): T
-- dt for Heartbeat loops of effects: 0 while frozen.
function Clock.dt(dt: number): number
function Clock.freeze()
function Clock.resume()
function Clock.frozen(): boolean
return Clock
```
Szczegóły:
- Śledzone rzeczy w tablicach ze słabymi kluczami (`setmetatable({}, { __mode = "k" })`); tween wypada po `Completed`, emiter i smuga po `Destroying`/`AncestryChanged` bez rodzica.
- `freeze`: `tween:Pause()` dla grających, `emitter.TimeScale = 0`; `Trail` i `Beam` nie mają `TimeScale`, więc na czas zamrożenia zapamiętaj `Trail.Lifetime` i ustaw `Lifetime = 60` (smuga nie blednie), przy `resume` przywróć. Zapisz w `docs/ANIMACJE.md`, że zrzut smugi rób w ciągu 0,1 s od zamrożenia, a cząsteczki wypuszczone przed `freeze` stoją dzięki `TimeScale`.
- `resume`: odwrotnie, przesunięcie zegara o czas zamrożenia.
- Planista `after`: lista `{ at, fn, args }`, jedno połączenie `RunService.Heartbeat` zakładane leniwie przy pierwszym `after` i odpinane, gdy lista pusta (zasada 8); przy zamrożeniu nic nie odpala. Błąd w `fn` łap `pcall` i `warn` (jak `VfxController` :969–976), żeby jeden zły efekt nie zatrzymał planisty.
- Gra bez AnimLab nigdy nie woła `freeze`, więc zachowanie jest jak dziś (odpalenie najpóźniej klatkę po `task.delay`; to ta sama dokładność).

### D. Zamrożenie ruchu i efektów

**D1. `AnimationController.LabHold(model: Model, t: number?)` (nowe).** Gdy `t` jest liczbą, wszystkie ruchy postaci `model` (atak podstawowy, umiejętność) są próbkowane w chwili `t` od swojego startu i **nie są usuwane** po końcu (atak w `rest`, umiejętność `done`): `poseCharacter` dostaje dla trzymanych modeli `now = start + t` osobno dla ataku i umiejętności; drżenie po trafieniu (`flinches`) jest wtedy pomijane. `nil` puszcza ruch dalej od zamrożonego miejsca (przesunięcie `start` o czas trzymania, wzór `Hitstop` :604–615). Dodatkowo `AnimationController.LabClear(model)` usuwa ruchy i oddaje stawy (`release`). Tylko modele z `VaelthornPreview = true` mogą być trzymane (`LabHold` na innym modelu nic nie robi i ostrzega raz). Wierzchowce S96 i jeźdźców nie ruszasz.

**D2. `Vfx/Library` na zegarze.** Pomocnik `tween` :17 → `Clock.tween`; `emit` :42 i każde `Instance.new("ParticleEmitter")` (:242, :409, :494, :727, :802) → `Clock.track(e)`; `Trail`/`Beam` tworzone w `projectile`, `weaponTrail` :744, `beam`, `lineBeam`, `tether` → `Clock.track`; każde `task.delay` w pliku → `Clock.after`; każda pętla `Heartbeat` z `os.clock()` → `Clock.now()` i `Clock.dt(dt)` (pętla `tether` :923 `while os.clock() < ending` → `Clock.now()` i `task.wait()` bez zmian). Liczby czasów i wygląd **bez zmian**.

**D3. `Vfx/Pool`.** `later` :94 i `done` :107 → `Clock.after` (zamrożony efekt nie wraca do puli ani nie zwalnia budżetu w połowie). `Pool.activeCount` bez zmian.

**D4. `VfxController` i `CombatFxController`.** W `VfxController` każde `task.delay` w `onCast`, `onImpact`, `onExtra`, `Preview` (m.in. :241, :254, :268, :306 zostaje na `task.delay`, bo to blokada ruchu postaci gracza, nie efekt; :435, :461, :561, :669, :805, :826) → `Clock.after`. ### F. Klatki kontrolne: `src/shared/Logic/MotionKeys.luau` (nowy, ok. 180 linii, czysty)

```lua
export type KeyName = "start" | "peak" | "release" | "hit" | "strikePeak" | "land" | "follow" | "end"
export type Key = { name: KeyName, t: number }
export type Keys = { Key } -- sorted by t, names unique

function MotionKeys.attack(weaponType: string?, interval: number?): Keys
function MotionKeys.skill(skillId: string, loopUntil: number?): Keys?
function MotionKeys.monster(windup: number?, strikeNow: boolean?): Keys -- generated rig (Logic/Gait)
function MotionKeys.boss(bossId: string, attackId: string): Keys?
function MotionKeys.ability(abilityId: string): Keys? -- Elite II (Data/MonsterAbilities)
function MotionKeys.clip(length: number, hitMarker: number?): Keys
function MotionKeys.at(keys: Keys, name: KeyName): number?
```
Definicje (zapisz je w komentarzu nagłówka i w `docs/ANIMACJE.md` §3):
- **Atak podstawowy** (`timing = AttackPose.timing(AttackPose.motionFor(weaponType), interval)`): `start = 0`; `peak = timing.windup` (koniec zamachu, poza `windup`); `hit = timing.hitAt` (to jest czas serwera: `AttackPose.hitDelay` dla walki wręcz; dla ruchów z `ranged = true` ta sama chwila nazywa się `release`, a `hit` nie występuje, bo zależy od lotu); `follow = windup + strike + 0,3 · recover`; `end = total`.
- **Umiejętność** (`motion = SkillMotions.get(id)`, brak → `nil`): `start = 0`; `hit = SkillMotions.hitDelay(id)`, gdy ruch ma `hit` (czas serwera, ucięty do `MAX_HIT`); `release = motion.release`, gdy jest; `land = motion.land`, gdy jest; `peak` = największe `key.t` mniejsze od pierwszego z (`hit`, `release`), a gdy ich brak: `key.t` klucza o największej sumie modułów kątów ramion; `follow = h + 0,35 · (end − h)`, gdzie `h` = `hit` albo `release` albo `peak`; `end = SkillPose.duration(motion, loopUntil)`.
- **Potwór z generatora** (`w = windup or Gait.DEFAULT_WINDUP`): `start = 0`; `peak = w` (raise = 1); `hit = w` (serwer zadaje obrażenia telegrafu po `windup`); `strikePeak = w + Gait.STRIKE_SECONDS` (chwila, w której `strike = 1`: to tu ruch „uderza”); `follow = strikePeak + 0,3 · RECOVER_SECONDS`; `end = Gait.attackLength(w)`. Ze `strikeNow = true` (zwykły atak, `MonsterAttack` :306) wszystkie czasy przesuń o `−(w − 0,06)` i obetnij do ≥ 0, a `hit = 0` (obrażenia przychodzą razem ze zdarzeniem `atk`). **Różnica `strikePeak − hit` to pierwsza znana usterka** (0,14 s przy telegrafie, ok. 0,2 s przy zwykłym ataku, wobec tolerancji §2.2 ±0,03 s): wpisz ją do tabeli H5 dla S117.
- **Boss / Elita II**: jak potwór z `w = attack.windup` / `ability.windup` (`nil`, gdy brak bossa, ataku lub zdolności).
- **Klip**: `start = 0`, `hit = hitMarker` (gdy jest), `end = length`, `peak` i `follow` nie występują.
