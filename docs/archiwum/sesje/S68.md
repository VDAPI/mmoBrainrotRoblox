### A. `Logic/TooltipModel`: kolejność i model szczegółów

1. **Kolejność opisu sprzętu** (STATY 11). Rozbij `equipmentLines` na trzy funkcje i ułóż `build` tak:
   1. `name`, `type` (bez zmian); `ilvl` i `element` (szary nagłówek, bez zmian);
   2. obrażenia, obrażenia magiczne, `speed`, `dps` broni albo statystyki bazowe (obrona, życie), bez zmian w środku;
   3. sekcja „Cecha” z S62 (role `traitName` i `trait`; jeśli S62 postawiło ją gdzie indziej, przenieś ją tu); tylko dla typów z cechą;
   4. linie zwykłe (`tier == "regular"`) z paskiem jakości;
   5. linie legendarne, potem mityczne: sortowanie po `TooltipModel.TIER_ORDER = { regular = 1, legendary = 2, mythic = 3 }`, a w obrębie rzędu po indeksie w instancji (klucz `(rząd, indeks)`, bo `table.sort` nie jest stabilne; tak samo dla `fixedBonuses` nazwanych przedmiotów);

   ```lua
   export type DetailRef =
   	{ kind: "bonus", id: string, v: number, quality: number? }
   	| { kind: "trait", id: string }

Klucze `bonusInfo.*` są obowiązkowe dla każdego haka, każdego `param` i linii z S62–S64 (lista w G);

   - `pvp`: `tooltip.detail.pvp.<tryb>` z `{pvp}` jako ułamkiem w stylu języka (`0,6`): `Combat.pvpModifier` dla `same` i `only`, `Combat.pvp.dot` (S63) dla `ticks`, `Combat.pvp.lifesteal` (S63) dla `half`;
   - `situational`: gdy `Data/ItemWeights` oznacza efekt jako `situational` (wpis w `hooks` albo w `prefixHooks`), `tooltip.detail.situational` („Lepszy przedmiot” liczy ją w połowie).

   - `does`: `trait.<id>.info` z argumentami `TooltipModel.traitArgs(traitId, power, lang)` (A7), więc każda liczba w tekście pochodzi z `Data/ItemTraits` przy sile tego przedmiotu, żadna nie jest wpisana ręcznie;

   - `cap`: z `ItemTraits.capRef`;
   - `pvp`: gdy w języku jest klucz `trait.<id>.pvp` (G4), ten tekst z argumentami `traitArgs`, `{dot}` = `Combat.pvp.dot` i `{frost}` = `Combat.pvp.frostbite`; inaczej z mnożnika `TraitDef.pvp` (S62): 0 → `tooltip.detail.pvp.none`, 1 → `tooltip.detail.pvp.same`, inaczej `tooltip.detail.pvp.mul` z `{mul}`;
   - `nodes`: `tooltip.detail.nodes` z `{list}` z `traitNodes` (A6), węzły posiadane (`ctx.nodes[id] > 0`) pogrubione; pusta lista = brak wiersza (do S71 zawsze brak).

### B. Porównanie w procentach (`Logic/ItemScore`)

1. **Funkcje** (czyste, w `Logic/ItemScore.luau` z S67):
   ```lua
   export type Delta = { dmg: number, surv: number, support: number } -- percent points, rounded to 0.1
   function ItemScore.weaponDps(item: ItemInstance, classId: string): number
   	-- (mdmg for a class whose basicAttack.kind == "magic", else dmg) x speed; 0 for items without a weapon block
   function ItemScore.percentDelta(candidate: ItemInstance, replaced: { ItemInstance }, ctx: Context | string): Delta?
   ```
   `breakdown` z S67 używa `weaponDps` (bez liczenia DPS drugi raz w dwóch miejscach). `percentDelta` zwraca nil, gdy `replaced` jest puste (pusty slot) albo klasa nieznana. Algorytm:
   - punkty osi bez broni: dla każdego przedmiotu `b = breakdown(item, ctx)`, `dmg = b.dmg − weaponDps(item) × ItemWeights.WEAPON`, `surv = b.surv`, `support = b.support`; sumujesz po kandydacie i osobno po `replaced`; część linii = (kandydat − zastępowane) / `ItemWeights.PCT_POINTS`;
   - mnożniki `axes` klasy i ścieżki **nie** wchodzą do procentów (opisują tylko, jak bardzo ścieżka ceni oś przy „Lepszym przedmiocie”); wagi statystyk i cech ścieżki (`stats`, `traits`) wchodzą, bo opisują wkład statystyki w tej ścieżce. Jeśli `breakdown` z S67 mnoży osie przez `axes`, wydziel liczenie osi przed `axes` do `ItemScore.axisPoints(item, ctx)` i użyj go w obu miejscach;
   - część broni: gdy kandydat i zastępowana broń mają DPS > 0, `(dpsKandydata / dpsZastępowanej − 1) × 100`, inaczej 0; `dmg` = część broni + część linii;
   - wynik zaokrąglony do 0,1.
2. **W opisie** (`TooltipModel`, blok porównania, gdy `ctx.equipped` i slot jak dziś):
   - lista zastępowanych: `{ ctx.equipped }`, a dla kandydata dwuręcznego także `ctx.offhand` (jeśli jest);
   - kandydat do drugiej ręki przy dwuręcznej `ctx.mainHand` (wtedy `ctx.equipped` jest puste, bo broń dwuręczna zdjęła drugą rękę): bez procentów, tylko czerwona linia `compareNote` z istniejącym tekstem `equip.error.twoHanded`, także bez `ctx.equipped`;
   - gdy `ctx.class` jest podane i `percentDelta` coś zwróciło: najpierw `compareTitle` (jak dziś), potem po jednej linii roli `comparePct` dla `dmg` i `surv` (`tooltip.compare.dmg`, `tooltip.compare.surv` z `{v}` = znak + liczba z jednym miejscem po przecinku + „%”, minus jako „−”, zielony `#2E8B3E` albo czerwony `#B8423A` jak w `compareLines`), dla `support` tylko gdy |Δ| ≥ 0,05 (`tooltip.compare.support`); osie z |Δ| < 0,05 pomijasz; potem szara linia `compareNote` z `tooltip.compare.estimate`; przy kandydacie dwuręcznym z założoną drugą ręką jeszcze `tooltip.compare.offhand` z `{item}`;
   - potem dotychczasowa lista statystyk (`compare`) bez zmian, więc test S31 („`compare` dokładnie 1”) przechodzi; bez `ctx.class` nie ma linii `comparePct`.
   - kontekst dla `ItemScore`: `{ classId = ctx.class, level = ctx.level, pathId = ctx.pathId }`.
3. **Jeden wybór zastępowanego przedmiotu** (czysty, w `Logic/ItemScore`):
   ```lua
   -- Item the candidate would replace: the slot's item; rings: the weaker of ring1 / ring2 by score, nil while
   -- a ring slot is free (the new ring goes there).
   function ItemScore.replaced(def: Items.ItemDef, equipment: { [string]: any }, ctx: Context | string): ItemInstance?
   ```
   Przenieś tu lokalne `replaced` z `client/Controllers/LootComfortController.luau` (43–53 w `05b859d`, po S67 z `ctx`) i wołaj ją z karty, z `ItemTooltip.equippedFor` (C6) i z `/tooltip` (F1), żeby karta, opis i admin porównywały z tym samym przedmiotem.

### C. Okienko szczegółów w grze (`client/UI/Components/ItemTooltip.luau`, `client/UI/DragDrop.luau`)

1. **Wiersze, które reagują.** W `build` każda linia z `entry.detail` jest owinięta w `TextButton` (`Text = ""`, `AutoButtonColor = false`, `BackgroundTransparency = 1`, pełna szerokość, `AutomaticSize = Y`) z dotychczasowym `line`/`bonusRow` w środku. Zdarzenia (Fusion 0.3, `[Fusion.OnEvent "…"]`):
   - `Activated` (stuknięcie na telefonie albo kliknięcie myszą w przypiętym opisie): otwiera szczegóły tej linii, a ponowne na tej samej zamyka;
   - `MouseEnter`: gdy opis jest przypięty (C3), otwiera szczegóły z boku; `MouseLeave`: gdy otwarte są szczegóły tej linii, zamyka je.
   Na dotyku (`Fusion.peek(Device.Touch)`) wiersz dostaje po prawej, przed paskiem jakości, ikonę „i”: koło 18×18 (`UICorner` 1,0, tło `Theme.Colors.GoldDim`) z literą „i” (`Theme.Fonts.BodyBold`), a tekst linii zwęża się o 22 px. Ikonę rysujesz kształtem, nie znakiem ⓘ (czcionki motywu mogą go nie mieć). Na PC ikony nie ma. Oba panele (opis i założony przedmiot) działają tak samo.
2. **Panel szczegółów.** W `ItemTooltip.mount` nowy `Frame` w warstwie `Tooltip` (poza poziomą listą paneli, `ZIndex = 210`, szerokość `WIDTH`, pergamin jak opis, obramowanie w kolorze rzędu: zwykła `#1F4E9A`, legendarna i mityczna z `Rarities.get(…).textColor` jak w `bonusRow`, cecha `ItemTraits.COLOR` z S62). Stan modułu: `detail = moduleScope:Value(nil :: OpenDetail?)` z `OpenDetail = { ref: TooltipModel.DetailRef, item: ItemInstance, ctx: TooltipModel.Ctx, anchor: GuiObject, side: "right" | "below" }`. Treść z `TooltipModel.details(item, ref, ctx)`: tytuł (`BodyBold`, `Theme.TextSize.Body`), wiersze (`Small`; `does` ciemny, `cap`/`pvp`/`situational`/`range` szare, `growth` ciemny pogrubiony). Na dotyku w prawym górnym rogu przycisk „×” 28×28, który zamyka panel.
   - Pozycja (wirtualne piksele przez `Scale.toVirtual` z `anchor.AbsolutePosition`/`AbsoluteSize`): `side = "right"` (PC) obok prawej krawędzi panelu opisu na wysokości wiersza, a gdy brak miejsca, po lewej stronie całej grupy paneli; `side = "below"` (telefon) na panelu opisu tuż pod stukniętym wierszem, a gdy wychodzi poza dół ekranu, nad nim. Wysokość panelu weź z `[Fusion.Out "AbsoluteSize"]` do `Value` i przytnij `y` do `ekran.Y − 8 − wysokość`.
   - Zamykanie: zmiana `shown` (inny przedmiot) albo schowanie opisu ustawia `detail` na nil; na dotyku stuknięcie poza panelem szczegółów i poza wierszem-kotwicą zamyka je (`task.defer`, żeby stuknięcie w inny wiersz od razu otworzyło jego szczegóły).
