### B. Czysta logika (`src/shared/Logic/Premium.luau`)

**B1. Limity.**

```lua
-- Per-account shop counters (S120, account.shopLimits): purchases of each limited entry today and this week.
-- `day` is Time.dayNumber, `week` is Time.weekNumber (Monday 00:00 UTC, the same week as weekly quests, S98).
export type ShopLimits = { day: number, week: number, daily: { [string]: number }, weekly: { [string]: number } }
```

- `Premium.emptyLimits(): ShopLimits` = `{ day = 0, week = 0, daily = {}, weekly = {} }` (szablon w `AccountSchema` używa tej samej postaci; nie wywołuj `Logic/Premium` z `AccountSchema`, jeśli to robi cykl `require`: wtedy wpisz literał i test porównuje oba).
- `Premium.limitsOf(account: { shopLimits: ShopLimits?, dailyLimits: { day: number, protectScrolls: number }? }, now: number): ShopLimits`: **nowa tabela** (nigdy nie zmienia wejścia) z licznikami na dziś i ten tydzień: gdy `shopLimits.day ~= Time.dayNumber(now)`, `daily = {}`; gdy `shopLimits.week ~= Time.weekNumber(now)`, `weekly = {}`; `day` i `week` ustawione na bieżące. **Zgodność wstecz (jednorazowo):** gdy w nowej tabeli `daily.scroll_protection == nil`, a stare `account.dailyLimits.day == Time.dayNumber(now)`, to `daily.scroll_protection = dailyLimits.protectScrolls` (gracz, który dziś przed aktualizacją kupił 1–5 zwojów, nie kupi kolejnego tego samego dnia). Komentarz: `-- S120: reads the pre-S120 counter for the day of the update only; dailyLimits is never written again.`
- `Premium.usedOf(entry: Products.ShopEntry, account, now): (number, number)` = kupione dziś i w tym tygodniu (z `limitsOf`).
- `Premium.canBuy(entry: Products.ShopEntry?, account: { dragonShards: number, shopLimits: ShopLimits?, dailyLimits: any? }, now: number): (boolean, string?)`. Kolejność błędów (klucze Locale):
  1. `entry == nil` → `error.badRequest`;
  2. `entry.unavailable == true` → `premium.error.soon` (nowy klucz: S97 go nie dodała, użyła `premium.error.notOnSale`; dodajesz w G);
  3. `dailyLimit` i kupione dziś `>= dailyLimit` → `premium.error.dailyLimit` (istniejący);
  4. `weeklyLimit` i kupione w tym tygodniu `>= weeklyLimit` → `premium.error.weeklyLimit` (nowy);
  5. `account.dragonShards < entry.price` → `premium.error.shards` (istniejący);
  6. inaczej `true, nil`.
  Limit przed ceną: gracz bez waluty, który i tak wyczerpał limit, dowie się o limicie (to ważniejsza informacja). Przy limicie `0` (nigdy nie powinno wystąpić) wpis jest niekupowalny; `paywall.spec` pilnuje, że limity są `>= 1`.
- `Premium.countPurchase(entry, account, now): ShopLimits` = `limitsOf` + 1 w `daily[entry.key]` (gdy wpis ma `dailyLimit`) i w `weekly[entry.key]` (gdy ma `weeklyLimit`); wpis bez limitów zwraca `limitsOf` bez zmian (serwer i tak zapisuje tylko przy limicie, D1).
- **Usuwasz** stare `DailyLimits`, `usedToday`, `canBuyShop`, `countDaily` (grep `canBuyShop\|countDaily\|usedToday\|DailyLimits` w `src` i `tests` przed usunięciem: dziś to `PremiumShopService.luau:57,67`, `PremiumShop.luau:204`, `premium.spec.luau:12–40`; po S88–S119 może być więcej, wtedy przestawiasz każde miejsce). `Premium.day` zostaw, jeśli ktoś go używa; nowy kod liczy dzień przez `Time.dayNumber`.
