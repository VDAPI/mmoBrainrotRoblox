**A2. Funkcje** (sygnatury; typy `SkillDef` i `Behaviour` jak w module po S55):
```lua
-- S79 (ROZWOJ 12.3): circle, cone, line and chain spells are "area", everything else "single".
-- Not Traits.isAreaSkill (S63): that one also counts traps, for the 1/3 on-hit trait share.
function Skills.tag(def: SkillDef): "area" | "single"
function Skills.isSpell(def: SkillDef): boolean -- has values.dmg (spells get spellCost / areaCost)
function Skills.areaApplies(tag: string, count: number, secondary: boolean): boolean
function Skills.singleApplies(tag: string, secondary: boolean): boolean
function Skills.areaCount(def: SkillDef, inCircle: number, struck: number): number
function Skills.spellBonus(tag: string, count: number, secondary: boolean, hooks: { [string]: number }?): number
function Skills.resonanceMul(manaFraction: number, pct: number): number
function Skills.castZones(def: SkillDef, behaviour: Behaviour, wave: number, percent: number, hookPct: number, inCircle: number): { Zone }

function Skills.areaKillMana(tag: string, killed: boolean, dealt: number, pct: number, maxMana: number): number
function Skills.channelGuard(kind: string, value: number, duration: number): GuardSpec?
function Skills.castGuard(def: SkillDef, value: number): GuardSpec?
function Skills.areaRadius(def: SkillDef, pct: number): number?
function Skills.manaShieldSplit(amount: number, share: number, mana: number, costPct: number): (number, number)
```
Działanie:
- `tag`: `"area"` dla `def.type` z zestawu `circleSelf`, `circleTarget`, `cone`, `line`, `chain` (zamrożona tablica w module), inaczej `"single"`. `isSpell`: `def.values ~= nil and def.values.dmg ~= nil`.
- `areaApplies`: `secondary or (tag == "area" and count >= SkillData.AREA_MIN_HITS)`. `singleApplies`: `tag == "single" and not secondary` (każde główne trafienie czaru w jeden cel, także drugi pocisk Pocisku 10B; przebicie i rozprysk to trafienia poboczne).
- `areaCount`: przy `def.randomTarget` zwraca `inCircle` (Burza Piorunów liczy wrogów w kręgu, choć piorun trafia jednego), inaczej `struck`.
- `spellBonus` (procent): `(areaApplies ? hooks["areaDamage"] : 0) + (singleApplies ? hooks["singleDamage"] : 0) + hooks["spellDamage"]`, brak tabeli albo klucza = 0. Jedna suma, bo premie do tagu i do czarów to jeden czynnik (model `SkillEngineMag`).
- `resonanceMul`: `1 + pct / 100`, gdy `pct > 0` i `manaFraction × 100 >= SkillData.RESONANCE_MANA`, inaczej 1. Ułamek many liczy się **przed** zapłatą kosztu tego czaru (G3).
- `castZones` (ROZWOJ 14.4: strefa `areaLingering` raz na rzucenie, przy pierwszej fali, osobna od strefy przełomu). Typ `Zone = { pct: number, duration: number, radius: number, kind: string, slow: number?, element: boolean? }`, gdzie `pct` to procent ataku jednego tyku na sekundę. Dla `wave ~= 1` pusta lista. Przy fali 1:
  - strefa przełomu (gdy `behaviour.lingering`): `{ pct = percent × spec.pct / 100, duration = spec.duration, radius = spec.radius or def.radius or 8, kind = spec.kind, slow = spec.slow }`; gdy `spec.kind == "element"`, dodatkowo `element = true`;
  - strefa haka (gdy `hookPct > 0`, `tag(def) == "area"`, `isSpell(def)` i `def.type` to `circleSelf` albo `circleTarget`): `{ pct = percent × (def.hits or 1) / (if def.randomTarget then inCircle else 1) × hookPct / 100, duration = SkillData.AREA_LINGER_SECONDS, radius = def.radius or 8, kind = "element", element = true }`. „Procent od wartości czaru na cel, czyli `dmg` × fale, a przy `randomTarget` podzielony przez wrogów w kręgu” (14.4). Przy `randomTarget` i `inCircle < 1` strefy haka nie ma (nie ma między kogo dzielić; pusta pierwsza fala dawałaby inaczej pełne `dmg × fale` na każdego wroga, który wejdzie później). Łańcuch, stożek i linia stref nie dostają: dziś strefa przełomu istnieje tylko w kręgach (linia w DECYZJE).
- `zoneKind`: `fire` → `"burn"`, `ice` → `"frost"`, `lightning` → `"spark"`, nil i inne → `"arcane"` (klient rysuje nieznany rodzaj kolorem żywiołu z `el`).
- `areaKillMana`: `maxMana × pct / 100`, gdy `tag == "area"`, `killed`, `dealt > 0` i `pct > 0`, inaczej 0.
- `channelGuard` / `castGuard`: `GuardSpec = { kind = "damageReduction", value, duration, category = "own", skillId, target = "self" }`. `channelGuard` zwraca spec z `skillId = "arcanist_masterMind"` tylko dla `kind == "channel"` (komentarz: `-- S80 adds "beam"`), `value > 0` i `duration > 0`; inaczej nil. `castGuard` zwraca spec z `skillId = "destroyer_mantle"` i `duration = ((def.hits or 1) − 1) × (def.interval or 0.4)` tylko dla `def.id == SkillData.VORTEX_SKILL`, `value > 0` i `duration > 0` (do ostatniej fali tego Wiru, 12.4).
- `areaRadius`: dla `tag(def) == "area"`, `def.type` `circleSelf` albo `circleTarget` i `def.radius ~= nil`: `def.radius × (1 + pct / 100)`; w pozostałych przypadkach `def.radius` bez zmian (promień skoku łańcucha to nie krąg).
- `manaShieldSplit` (Tarcza Many z hakiem `manaShieldCost`, znak „plus = więcej many”): `want = amount × share / 100`, `rate = max(0, 1 + costPct / 100)`; przy `rate == 0` zwraca `(want, 0)`; inaczej `absorbed = min(want, mana / rate)`, `spent = absorbed × rate`. Przy `costPct = 0` wynik to dokładnie dzisiejsze `min(mana, want)` dla obu wartości.

**A3. `Skills.cost` czyta haki `areaCost` i `spellCost`** (ROZWOJ 14.4; jedna funkcja dla serwera, paska, opisu i wiki). W miejscu, w którym S54 mnoży przez `1 + costPct / 100`, dla `isSpell(skill)` dodaj do sumy procentów `hookValue(mods.hooks, "spellCost")`, a gdy dodatkowo `tag(skill) == "area"`, także `hookValue(mods.hooks, "areaCost")`: `× max(0, 1 + (costPct + spellCost + areaCost) / 100)`. Pomocnik `local function hookValue(hooks: { [string]: number }?, id: string): number return if hooks then hooks[id] or 0 else 0 end` (literał w każdym wywołaniu). Znak: **plus = drożej** (Niestabilna Moc i Przeciążenie +10 → 30, Oszczędny Splot i Przepływ ujemne, ROZWOJ 12.4–12.5). Haki wchodzą do kosztu bazowego (`base` z S62), przed oszczędnością `costReduce`, więc obie zwracane liczby je zawierają (Przeciążenie podnosi też moc Arkanisty liczoną od `base`, i tak ma być). `trapCost` z S76 zostaje, jak jest (inny znak: tam plus = taniej). Komentarz przy `CostMods.hooks` opisuje obie konwencje: `-- cost hooks in %: areaCost / spellCost (S79) plus = dearer; trapCost (S76) plus = cheaper (a discount)` (S80 B4 dopisze tam `chargeCost`, plus = drożej). Nie dokładaj nowego argumentu pozycyjnego.
